# 告警通知配置指引（邮件 / 飞书 / 钉钉 / 企业微信）

> 给非运维背景的操作者。目标：把「监控告警发去哪」从「写服务器 `.env` + 重新部署」换成**管理页里点着填**，
> 并知道每个值**去哪拿**、怎么**轮换**、怎么**验收**。
> ⚠️ 平台页面会改版——凡带「以实显为准」的字段，照各平台控制台当刻显示填。
> 我方侧细节（管理页填写步骤、上线顺序、验证配方）见 `docs/ops/first-deploy.md`「通知怎么上线（三步）」与「监控」一节。

---

## 0. 一分钟看懂

- **告警发去哪** = 两条**互相独立**的通道：**邮箱**（SMTP，Alertmanager 原生发）+ **IM 群**（飞书 / 钉钉 / 企业微信，**配了哪个发哪个**）。
- 通知通道管理化片（2026-10-07）起：九项配置（SMTP 五件套 + 收件地址 + 三个 webhook + 钉钉加签密钥）都在
  **管理页 →「通知通道」** 填，**保存后 ≤30 秒生效 —— 不用重启、不用重新部署**（与旧 `.env` 写法不同）。
- 值班链路：Prometheus 判规则 → Alertmanager 汇集 → 邮箱直接发 / IM 群经告警转发器投递。

## 1. 邮箱（SMTP）——去哪拿

以 163 / QQ 邮箱最常见（现役就是 163）：

1. 登录**邮箱网页版** → 设置 → 找 **「POP3/SMTP/IMAP」** 一类开关（各家叫法略不同，以实显为准）。
2. **开启 SMTP 服务**。163 会弹一个「授权码」弹窗 / 让你发一条短信 —— 弹出来的那串字符就是**授权码**。
   - 🔴 **授权码 ≠ 登录密码**。把登录密码填进去 = 发不出信（这是最常见错误）。
   - 授权码往往**只显示一次**，复制下来存好；忘了就再走一遍流程重新生成（旧的作废）。
3. 记下三件：**SMTP 服务器**（163 = `smtp.163.com`，QQ = `smtp.qq.com`）· **端口**（这两家都是 **465**，SSL 直连）· **账号**（你的完整邮箱地址）。
4. 管理页对应填五行：`邮件服务器` / `邮件端口` / `邮件账号` / `邮件授权码`（这行输入框是密码框）/ `告警收件地址`
   （收告警的邮箱，可与你自己的邮箱相同；要多人收就**逗号分隔**写在同一行）。

（「监控活着」的心跳邮件只走邮箱、约每 24 小时一封 —— 邮件组配好后自然会来。）

## 2. 企业微信（现役通道）

1. 打开要收告警的**群** → 右上角「…」→ **群机器人** → **添加** → 新建（或选已有的）。
2. 复制它给的一条 **Webhook 地址**（形如 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=<机器人 key>`）。
3. 管理页 →「通知通道」→ `企业微信机器人地址` 粘贴保存。
4. ⚠️ 泄露 / 轮换时在机器人设置里**重发**一条新 webhook（旧地址即废）—— 见 §6。

## 3. 飞书

1. 群 → **设置** → **群机器人** → **添加机器人** → **自定义机器人** → 起个名字（如「告警」）。
2. 复制 **webhook 地址**（形如 `https://open.feishu.cn/open-apis/bot/v2/hook/<一长串>`）。
3. 管理页 →「通知通道」→ `飞书机器人地址` 粘贴保存。

## 4. 钉钉（**加签** 形态）

1. 群 → **智能群助手** → **添加机器人** → **自定义** → 安全设置**勾「加签」**
   （⚠️ 不要选「自定义关键词」「IP 白名单」—— 我们的转发器按**加签**方式签名）。
2. 保存后会给你**两条**信息：**Webhook 地址** + **加签密钥**（`SEC` 开头）。
3. 管理页 →「通知通道」→ `钉钉机器人地址` 与 `钉钉加签密钥` **两条都要填**（只填一条 ⇒ 钉钉通道**不启用**，
   页面显示「未就绪（缺 1 项）」、且 10 分钟后会来一条 `NotifyDingtalkIncomplete` 告警提醒你 —— 这是设计，不是故障）。

## 5. 安全增益（为什么值得搬进管理页）

- **加密存储**：九项（含 SMTP 授权码与三条 webhook —— webhook URL 本身即凭据）在数据库里 **AES-256-GCM 加密**，
  不再落服务器 `.env`（也不再进 `.env` 备份）。
- **掩码写**：保存后页面**只显示指纹**（12 位摘要）—— **任何角色都读不回原文**（含我方）；**覆盖写入**是唯一修改方式。
- **审计留痕**：每次写入 / 清空都进管理页「审计」第一页签（谁、何时、指纹变化），值本身脱敏。
- **权限**：写入（保存 / 清空）**仅超级管理员**；读取可看状态（已配置 / 未配置 + 指纹）。

## 6. 轮换（怀疑泄露 / 平台重发）

任一条目 = **平台后台重新生成** ⇒ **管理页覆盖写入** ⇒ **指纹变化（肉眼可验）** ⇒ ≤30 秒生效、**全程不重启任何容器**：

| 通道 | 怎么「重新生成」 | 覆盖哪一行 |
|---|---|---|
| 企业微信 / 飞书 | 群机器人设置里**重发 / 重新复制** webhook（旧地址即废） | `企业微信机器人地址` / `飞书机器人地址` |
| 钉钉 | 机器人安全设置里重新生成**加签密钥**（webhook 可不动或一起重置） | `钉钉加签密钥`（+ `钉钉机器人地址`） |
| 邮箱 | 邮箱后台**重新生成授权码**（旧的作废） | `邮件授权码` |

**泄露应对**：先在平台侧重发 / 重置（旧值即废），再照上表覆盖；随后管理页「审计」可核对操作历史。

## 7. 验收（真人项；照 `first-deploy.md`「通知怎么上线（三步）」执行）

1. 管理页两组组尾都显示 **`已就绪`**（邮件组 5/5、钉钉组 2/2；没启用的通道保持「未配置」——它不参与）。
2. 触发一条测试告警（最省事：`docker stop ftl-grafana` 等 2 分钟，再 `docker start ftl-grafana`）。
3. **预期**：约 2–3 分钟后，**邮箱收到真邮件** + **已配的 IM 群收到真消息**（`ServiceDown`）。
4. 轮换演练：照 §6 给企微**重发**一条 webhook ⇒ 管理页覆盖 ⇒ 指纹变化 ⇒ 再触发 ⇒ **新群收到**。

## 8. 入口

- 管理页：`https://<你的域名>/admin` →「通知通道」
- 平台后台：企业微信（群机器人）· 飞书（群设置 → 群机器人）· 钉钉（智能群助手）· 邮箱（网页版设置里的 SMTP 开关）
- 我方手册：`docs/ops/first-deploy.md`「通知怎么上线（三步）」；告警总览见「监控（看板与告警）」一节。
