# 支付宝商户号 + 沙箱配置指引（支付片配套）

> 给非运维背景的操作者。目标：把「充值」从沙箱练手一路配到生产可收钱。
> ⚠️ 平台页面会改版——凡带「以控制台实显为准」的字段，照支付宝页面当刻显示填。
> 我方侧细节（**管理页填写**、开关）见 `docs/ops/first-deploy.md`「支付怎么上线（五步）」。

---

## 0. 一分钟看懂

- **商户号** = 让支付宝允许你「收钱」的资格（要营业执照实名）。
- **沙箱** = 支付宝给的「假钱练手环境」：不用资质、不花钱、不审核，先把全链跑通。
- 玩家会看到：钱包页点充值 → 跳支付宝收银台 → 付款 → 回游戏自动到账。

## 1. 资质前置（决定「能不能真上线」，尽早确认）

| 项 | 要求 | 备注 |
|---|---|---|
| 主体 | **企业或个体工商户**（手机网站支付类产品；个人支付宝一般不能签） | 没有营业执照 ⇒ 先办个体户（各地线上可办，通常几天） |
| 域名 | 签约时填网站信息；网站支付类**通常要求 ICP 备案**（以签约页为准） | `<DEV_HOST>` 备案状态先自查，没备案会卡审核 |
| 费率 | 充值按笔收费，约 0.38%–0.6%（以签约页为准） | 我们侧提现手续费=0；成本=充值费率 |

**沙箱不受以上任何一条限制——先办沙箱，别等资质。**

## 2. 沙箱配置（现在就能做，约 30–60 分钟）

入口：`https://open.alipay.com`（开放平台）→ 登录 → 控制台 → **沙箱**（「开发服务/沙箱环境」入口，以实显为准）。

1. 进沙箱即自动分配：**沙箱 APPID** · **沙箱买家账号**（付款用，自带虚拟余额）· **沙箱卖家账号**（商户视角，页面上能查到 **PID**）。
2. **生成密钥**：开放平台「开发助手/密钥工具」（网页版或下载「支付宝密钥生成工具」）→ 算法选 **RSA2（SHA256withRSA，2048 位）** → 生成两件：
   - 「应用私钥」（PEM 文件，**只留在你手里/服务器**）
   - 「应用公钥」（PEM 文件，上传给支付宝）
3. **上传应用公钥**：沙箱应用 → 设置 → 接口加签方式 → 选 **「公钥」模式**（⚠️ **不要选「证书」模式**——我们的实现是公钥模式，证书模式签名不同、会全失败）→ 粘贴应用公钥保存。
4. 保存后页面会显示 **「支付宝公钥」** → 复制保存（注意：是**支付宝**公钥，不是你的应用公钥——把应用公钥当支付宝公钥填 = 验签必失败，这是最常见错误）。
5. **沙箱网关地址**：沙箱页会显示；当前一般为 `https://openapi-sandbox.dl.alipaydev.com/gateway.do`（**以沙箱页实显为准**）。
6. 把六件套在**管理页 →「支付渠道」**填上（见 §4 总表），联调「下单 → 付款 → 回调 → 入账 → 退款」全链。
   - ⚠️ **回调必须公网可达**：沙箱付款后支付宝要回调 `https://<DEV_HOST>/pay/notify/alipay` ⇒ 联调在**部署到服务器之后、开开关之前**做（见 §5 顺序）。
   - 沙箱坑：wap 收银台还原度有限（页面样式可能怪，以链路为准）；沙箱单会原路退回沙箱买家；付款时用**沙箱买家账号**登录。

## 3. 生产商户号申请（可与沙箱并行启动，审核要几天）

1. 用**企业/个体户支付宝**完成商家实名（商家中心 `b.alipay.com`，或在开放平台注册时走企业认证）。
2. 开放平台**创建应用**（类型「网页/移动应用」）。
3. **产品中心 → 手机网站支付 → 签约**：填网站信息（`<DEV_HOST>`）、经营场景等 → 提交审核。
4. 审核通过后：在**生产应用**里重复 §2 的第 2–4 步（生成/上传密钥、取支付宝公钥）→ 记下 **APPID** 与 **商户 PID**。
5. 生产与沙箱**用两套密钥**，互不混用。

## 4. 交给我方的值（总表）

> 填写位置 = **管理页 →「支付渠道」**（**不是** `.env` —— 支付配置管理化片起，凭据**加密存储**在平台数据库里）。六项逐项对照：

| 管理页字段 | 沙箱期 | 生产期 | 说明 |
|---|---|---|---|
| `应用 APPID` | 沙箱 APPID | 生产 APPID | 明文（页面可回读） |
| `应用私钥` | 沙箱应用私钥 | 生产应用私钥 | 粘贴 **PEM 全文**或 **base64 一行**均可（服务端自动归一）；**保存后只回指纹——原文任何人都读不回**（含我方） |
| `支付宝公钥` | 沙箱**支付宝**公钥 | 生产**支付宝**公钥 | 同上两态均可；⚠️ 是**支付宝**公钥，不是自己的应用公钥 |
| `商户 PID` | 沙箱卖家 PID | 生产商户 PID | 回调「seller_id 校验」的真源；填错 ⇒ 回调全 failure（钱在支付宝、单不推进） |
| `渠道网关地址` | 沙箱网关 | **留空**（默认生产网关） | 沙箱期才填；生产就留空 |
| `对外站点基址` | `https://<DEV_HOST>` | 同 | 生成收银台跳转与回调地址用 |

- **安全增益**：凭据**加密存储**（AES-256-GCM 静态加密），**不再落服务器明文 `.env` 文件**、也不再随每小时备份走；**敏感值只经你手** —— 你自己在管理页粘贴，保存后**连我方（和任何管理员）都只能看到指纹**、读不回原文；填完把「六项都显示已配置」告诉我即可，我按**指纹与全链**帮你核对。
- **保存即生效**：下一次渠道调用就用新值 —— **不用重启、不用重新部署**（与老的 `.env` 方式不同）。
- **开关保持关**（`pay.rechargeEnabled=false`）时玩家面完全不可见，填错零风险。

## 5. 顺序总览（与我方纪律对齐；与 `first-deploy.md`「支付怎么上线（五步）」逐步对应）

1. `push master` → 打 tag `v*` → release 部署（服务器 `.env` 先补两枚根信任锚 —— `PAY_CONFIG_ENC_KEY` / `PAY_CHANNEL_PULL_TOKEN`，见手册 ②）。**部署本身就是暗上线**：开关默认关，玩家不可见。
2. 管理页 →「支付渠道」填**沙箱**六值（§4 总表）→ 沙箱联调（你是那天的"玩家"；我同步给逐条对单清单：每步在钱包页/管理页/日志看什么）。⚠️ 开关默认关会**拒单**（充值 15008）：联调前**临时**开 `pay.rechargeEnabled`，验完**立刻关回去**（手册五步第 3 步）。
3. 联调通过（含**轮换演练**：换密钥对 → 上传公钥 → 管理页覆盖私钥 → 指纹变化 → 全链复跑 —— 手册「密钥轮换」）→ 管理页换**生产**六值（`渠道网关地址` 清空）→ 可选：真 1 元小额自测一笔 → 开充值开关。
4. 提现开关更晚一点开（建议先观察几天充值侧）。

> 设计原文写「沙箱联调=打 tag 前置」；实操上沙箱回调需要公网域名，精确顺序是**「部署后、开开关前必过沙箱」**——效果一致：真实开关开启前一定过沙箱全链。
