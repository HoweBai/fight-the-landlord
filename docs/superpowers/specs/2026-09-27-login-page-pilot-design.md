### 3.1 🔴 粗算**不够** —— 这是预期结果，不是意外

要压 1222 → 750 需要约 **350**（注册态还更多），而上表只给 **~230**。
⇒ **大概率落到「卡内滚动」**。若要压进去，下面**三个杠杆至少得动一个**：

| 杠杆 | 省 | 代价 |
|---|---|---|
| **删第二颗提交按钮**（合并成一颗） | ~108 | ⚠️ 动探针（R649）+ `login-screen.test.ts` 三处断言 |
| **确认密码挪到密码旁边**（并排，不占独立一行） | ~148 | 仅注册态；`login.vue` 自己的注释就说这是「表单设计」 |
| 接受**卡内滚动** | 0 | 登录页出现滚动条，观感扣分（但比字段挤成一团好） |

⭐ **实施时先按 ~230 压、真浏览器量出实际高度，再决定要不要动杠杆** ——
**不要在没量之前就砍功能**。量出来的数字写进 §6 的验收记录。

⇒ **目标是把单列压进 750；压不进去就卡内滚动兜底**（滚动是兜底、不是首选）。
**精确账目由真浏览器实测定稿，不在这里推算** —— 本仓为「推算的尺寸」付过代价。

## 4. 明确不做（YAGNI）

| 不做 | 为什么 |
|---|---|
| **不删第二颗提交按钮** | ⚠️ **R649：真浏览器探针靠点它走注册路径**。样板的目的**只是验视觉** —— 动探针会把变量混进来，到时分不清「不好看」是视觉问题还是探针问题。视觉上做成**主次分明**即可；等视觉语言拍死后再单独决定要不要合并成一颗 |
| 不改 `submit()` / `auth.signIn` / `auth.signUp` | 逻辑已经写好，本次是**纯视觉** |
| 🔴 **不改 `uni.scss` 里任何令牌的「值」** | 令牌是**全局**的 —— 改一个值会**同时改掉其他三页**，而它们还没重做。需要新色就在 `login.vue` 里**局部**写（`$ftl-color-gold` 这类**引用**当然可以用，禁止的是**改定义**）。拍死之后才决定要不要回写令牌 |
| 不改协议、不动后端 | 登录页只走 REST，本来就不需要 |
| 不接 `$ftl-art-*` 七个槽 | 总规格 §3.1：槽位接线在片②③ |

### 验收记录（2026-09-27 实测 · Task 2b 布局修复后订正）

环境：无头 Chrome（**k=0.7547**）+ dev server；`scripts/measure-table.mjs`（canvas 列 = 画布坐标；画布 1334×750）。量法 = Task 2b 简报的两条 `Runtime.evaluate`（逐字）+ measure-table 命令（逐字）。

🔴 **先订正初版判据（控制者自己的文本缺陷 —— Task 2b 因它而生）**：初版记的判据是「`.login__panel` **可见高** ≤ 750」。**那条判据零判别力** —— 一个被 flex 挤压的滚动容器**永远** ≤ 750（恒真）。它报了 `455.4 ≤ 750 ✅`，而真实状态是：面板被挤压 ⇒ 面板内部滚动 ⇒ **提交按钮被裁**（登录态卡在下沿、注册态整行看不见）。**真判据（Task 2b 起用）**：① `.login__panel` 的 `scrollHeight − clientHeight` 必须 = **0**（面板不得内部滚动）；② `.login` 的 `scrollHeight` 才是**内容总高** —— 拿它跟 **750** 比。

**改前基线（同一套真判据，修复前量的）**：面板内部滚动 **39**（登录）/ **169**（注册）；被挤压时 `.login` 的 `scrollHeight` **假显 750**（挤压把溢出藏进了面板 —— 这正是旧判据的陷阱形态）。

**改后（Task 2b 压缩 = logo 高 96 · 标题 `$ftl-font-lg` · 面板内边距 `$ftl-space-6` · 面板/整列 gap `$ftl-space-4`）**：

| 项（画布 px） | 登录态 | 注册态 |
|---|---|---|
| `.login__panel` 内部滚动量（scrollHeight − clientHeight） | **0 ✅** | **0 ✅** |
| `.login` `clientHeight`（可见高） | 750 | 750 |
| `.login` `scrollHeight`（内容总高） | **750**（= clientHeight ⇒ 无滚动；按子元素求和 ≈ **733**，余量 ≈ 17） | **872**（真滚动 ⇒ 超 750 共 **122**） |
| 提交行未滚动时完整可见？ | **是** ✅ | 否（底边被切 7.1（屏幕 px）；滚动 122 后完整可见） |
| 是否装得下 | ✅ | ❌（超 122） |
| 杠杆决定 | 不需要 | **杠杆③「接受滚动」**（理由见下） |

**注册态仍超 750 ⇒ §3.1 三杠杆里只能这么选**：①「删第二颗提交按钮」= §4 明令不做（动探针 R649）；②「确认密码挪并排」（~148，仅注册态）= **表单设计改动，不在本片范围 —— 下一轮可做**；⇒ 本轮选 ③ **接受滚动**。⚠️ 实现形态是 **整列滚动**（`.login` 滚、**面板不滚** —— Task 2b 订正）：用户能滚到按钮（`register-scrolled.png` 佐证），而不是旧形态「面板内滚动把按钮裁掉」。

截图：`.tmp_shots/pilot-login.png`（登录态：提交行**完整可见**；幽灵按钮已改为内容宽、贴右下 —— 实测宽 398.8，原为 1302 横跨画布）/ `.tmp_shots/pilot-register.png`（注册态**未滚动的自然态**：底边被切 ≈7px 是兜底态的真实呈现；均以 `--hide-scrollbars` 采集）。

### 验收结论（2026-09-27 · Task 2c 定稿）

**用户 2026-09-27 的三条裁决**：
① **视觉语言由控制者定**（用户原话：「视觉语言你来定，统一风格就行」）② **修**幽灵按钮的涂装 ③ **注册态超 122 不动**（不用杠杆②）

**结论**：

1. **视觉语言拍板** —— 定稿表已写回总规格 **§5.2.1「视觉语言定稿」**（其余三页照它做）。
   本页据此收口三处：新令牌 `$ftl-color-danger-on-dark`（**只加不改**，扶正「借 `-bg` 当文字色」的语义滥用，
   评审 T2-M5）· 幽灵按钮**补涂装覆盖**（`ftl-btn` mixin 的白底 + `btn2` 贴图 ⇒ 透明底 + 虚线描边，
   评审 T2-M3，白板子已消失，§6 复测记录附计算样式自证）· 面板 alpha 0.55 → **0.62**（下半截压在浅色渐变区时立得更住）。
2. **注册态 872 > 750 是「已接受」的终态，不是待修缺陷** —— 用户裁决 ③ **不动杠杆②**（确认密码并排），
   **整列滚动就是它的处置**（可滚到按钮，`register-scrolled.png` 佐证）。
   ⚠️ 归错提醒：Task 2c 执行中途曾量到 **857** —— 那是幽灵按钮涂装块落地时**漏抄 `flex: 0 0 auto;`
   造成的静默回归**（幽灵钮在注册态被压回 `min-height` 56，吸收 14.4px），已由评审抓出、
   订正的简报要求恢复；**恢复后复测 = 872、幽灵钮 70.4**，与 Task 2b 几何逐字相同（§6 复测记录）。
   **857 不是终态，任何地方不得拿它当验收值。**
3. **判据**（Task 2b 的真判据，本片沿用）：面板内部滚动 **0（登录）/ 0（注册）**；
   `.login` 的 `scrollHeight` = **750**（登录，自然高 732.8 ≈ 733，装得下）/ **872**（注册，超 122 ⇒ 整列滚动兜底，
   用户已知情接受）。
