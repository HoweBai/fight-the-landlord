## 0. 一句话

把 App 端四页（**登录注册 / 玩法大厅 / 开始游戏 / 牌桌**）按腾讯《欢乐斗地主》的观感重做，

## 1. 背景：用户要什么、不要什么

**用户原话（2026-09-26 多选）**：要重做的理由是
**「视觉：不好看、不像棋牌游戏」** ＋ **「操作：玩法步骤不顺手」**。

⚠️ **没有**选「真机体验：卡/适配/白屏」，也**没有**选「整体升级、没有具体不满」。
⇒ 这是一次**真正的界面重开发**（新视觉体系 + 新交互设计），**不是换皮**，
**也不是加功能**（个人中心/设置/音效那类不在本批）。

**操作卡点（用户四选全中）**：

## 4. 协议与服务端：6 条改动

> **用户原话是「协议不变」**。以下是**全部**破口，逐条记账。**除 ④ 外都是加法。**

| # | 方向 | 改动 | 性质 |
|---|---|---|---|
| ① | 上游 | **新路由** `GET /api/base-score-levels` → `{ levels: { name, baseScore }[] }`<br>⚠️ **订正（2026-09-27）**：原写 `GET /api/rooms/options` —— 改名，因为这条**打到 `user-service`**（那里有 DB），叫 `rooms/options` 会让人找错服务。详见片规格 §2.3 | 加法，🔴 **要改 `docs/design.md` §7.1 的路由表**（加在 **user-service** 那组） |
| ② | 入站 | `room.match` 加 `baseScore: number`（**必填** —— 片规格 §2.4 订正：可选会让撮合键多出 `undefined` 这一维） | 加法 |
| ③ | 出站 | `PlayerView.bidPhase` 加 `kind: 'call' \| 'rob'` | 加法 |
| ④ | 出站 | `lastPlayedHand` + `lastPlayerIdx` **退役** → `recentActions`（窗口 2） | 🔴 **破坏性** |
| ⑤ | 入站 | `POST /api/rooms` 的 `baseScore` 加「必须属于档位表」校验 | 收紧 |
| ⑥ | 出站 | `PlayerView` 加 `baseScore: number` | 加法 |

### 4.1 ① 底分档位表（片②）

- **形态**：`{ name: string, baseScore: number }[]`。
  🔴 **名字与数字必须同源** —— 名字放前端、数字放服务端就是**第二真源**，正是本仓反复清掉的形态。
- **可配置**（D7）：由服务端 **env** 提供，带缺省值。
  ⇒ 判据：「缺省值合法」＋「`DEFAULT_BASE_SCORE` 属于档位表」。
  ⚠️ **档位名是中文** ⇒ 值的编码方式（中文直写 / 只配数字+名字另表）**在计划里定** ——
  **env 里传中文跨 docker compose 有踩坑风险**（编码/转义），别想当然。
- ⚠️ 档位数字在 MVP 里**只是观感**（无货币 ⇒ 底分只影响结算面板上分差的数字大小）。
- ⚠️ **网关路由顺序**：`@Get('rooms')` 与 `@Get('rooms/options')` **谁先声明** ——
  `packages/api-gateway/src/health/health.controller.ts:7` 的注释记着同类坑（**静态路由必须先于根路由**）。**这条要进判据。**

### 4.2 ② 选底分生效（片②）

- `room.match` 入站加 `baseScore: number`（**必填** —— 片规格 §2.4 订正：可选的话撮合 key 那一维可能是 `undefined`，必填让「不同底分**不会**被撮进同一个房」在类型上就成立）—— **这才是「选底分」真正生效的地方**。
- 撮合**天然按底分分组**：`matchQueueKey(mode, baseScore, region)`（`packages/room-service/src/match/match.service.ts:67`）多一维；
  `MatchTicket` 带上它并穿线到 `addToQueue`/`cancelQueue`/`processQueue`/`failMatch`。**成本：中等偏小。**
- ⚠️ **机器人补位也要拿房间的底分**（`createGameRoom` 的既有口子）。
- 非法值报哪个码 → 计划里**挑一个既有码，不新造**。

### 4.3 ③ 叫/抢阶段（片③）

- **只加出站，入站一个字不改。**
- 🔵 **已核实**：`game.bid` 的载荷是 `{ grab: boolean }`（`packages/protocol/src/messages.ts:45`）
  ⇒ **「叫」和「抢」在服务端本来就是同一个动作**。所以 `kind` 是**把已有的事实说出来**，不是新规则。
- ⚠️ **判据侧代价**：**R657**（`BidPanel.vue` 头注释）那条「文案**不随**叫/抢变化」要改形态 ——
  文案现在**随 `kind` 变化**，但依据是**服务端字段**而非前端反推。
  ⇒ 判据从「字面固定」改成「**只能从 `kind` 派生**」。

### 4.4 ④ 桌面历史牌（片③）—— 唯一的破坏性改动

**语义（用户逐字确认）**：

> 窗口 = **2 手**；**「不出」也占一手**。
> `A出3 → [3]`，`B出4 → [3,4]`，`C不出 → [4, 不出]`

- 每项：`{ seat: number, cards: Card[] | null }`（`cards: null` = 该座位「不出」）
- **顺序**：按发生顺序（旧 → 新），最多 2 条
- **全在服务端算** —— 「什么时候消失」是一条**显示规则**，不留给前端猜

🔵 **意外收益**：这条顺手**消灭一个现有 hack** —— 现在「不出」气泡是客户端**自己编的**
（`table.vue` 的 `bubble` / **R656**：服务端当时没有任何字段能表达「谁刚过了牌」，
只能等 ack 成功后本地造一个）。新规则下 `cards: null` 就是**服务端的原话** ⇒ **`bubble` 机制整条删掉**。

⚠️ **退役面要逐个列出**（`lastPlayedHand` / `lastPlayerIdx` 的所有读点）：组件、判据、真浏览器探针。

### 4.5 ⑤ 好友房的底分（片②）

- `POST /api/rooms` 的 body **本来就被网关原样转发**，`rooms.service.create()` **本来就接受** `baseScore?`
  （`packages/room-service/src/rooms/rooms.service.ts:166,176`）⇒ **只需加一条校验**。

### 4.6 ⑥ 牌桌显示场次（片③）

- 参考图 3/4 的牌桌**中央写着「欢乐经典新手场 底分15」**。
- ⚠️ `PlayerView` **没有** `baseScore` —— 这不是我猜的，是既有判据**白纸黑字**记着的：
  `apps/client/test/table-hud.test.ts:9`「想显示底分必须先扩协议 ⇒ 按 §1.7 不在本批」。
- 现在照参考图做 ⇒ **必须开**。前端拿 `baseScore` 去档位表（①）里查出名字 ⇒ 显示「XX场 底分N」。
- ⚠️ `table-hud.test.ts` 那条「HUD 不得出现『底分』」的判据**要改** —— 性质从
  「牌桌不得凭空多出底分」变成「牌桌只能显示服务端下发的底分」。

### 8.4 环境坑（本机，直接用）

- 🔴 **HBuilderX 版本必须 ≥ 5.26**（项目 `@dcloudio/*` = `3.0.0-alpha-5020620260914001`）。
  **版本偏低时真机白屏且无任何报错** —— 这个坑踩过。
- 🔴 **本机 DNS 缓存在路由器上** ⇒ 凡拿域名下结论先核 `nslookup`（记忆 `windows-dev-env-quirks` 第 12 条）
- 🔴 **本机没有 `flock` 与 `script(1)`** ⇒ 相关判据在本机**显式跳过**，只有 CI/Linux 能真跑。
  **别把「本机绿」当成「全绿」**
- 🔴 Windows Git Bash 会改写参数里的路径 ⇒ 碰容器内路径要 `export MSYS_NO_PATHCONV=1`
- **改 JSON/Markdown 的字符串替换要验** —— 有前例：替换提前闭合了 JSON 字符串，留下悬空文本 ⇒ `SyntaxError`
