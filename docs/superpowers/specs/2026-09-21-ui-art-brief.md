## 0. 一句话

**素材只做「底 / 框 / 图标」，一个字都不要画** —— 所有文字（「地主」「17」「倍数」…）
由 DOM 渲染。文字区**必须透明**，否则会和 DOM 的文字叠成两层。

## 1. 总则（每个槽都适用）

| 项 | 要求 | 为什么 |
|---|---|---|
| **格式** | PNG-24 + **透明通道** | 现有素材全是 PNG；`background-image` 需要 alpha |
| **交付尺寸** | **画布尺寸的 2 倍** | 画布 px 是**设计像素**；真机上 `k = 视口/1334`，桌面端可达 **~1.9** ⇒ 2× 才不糊 |
| **文字** | **不画**，文字区透明 | 见上文；改文案时不该重做图 |
| **命名** | `<槽名>.png`，槽名 = 令牌去掉 `$ftl-art-` 前缀 | 例：`landlord-badge.png` |
| **放哪** | `apps/client/src/static/ui/`（**平目录**） | ⚠️ `asset-budget.test.ts` 会**拒绝子目录**（`statSync` 对目录会拿到假的小体积 ⇒ 判据静默变松） |
| **预算** | `ui/` 目录 ≤ **1536 KiB**（`asset-budget.test.ts:31`；2026-09-29 实测 **857**）⇒ 新素材合计 **≤ 679 KiB** | 同上闸（片① 用户裁决 D13 把 400 抬到 1536，先例 U4） |
| **授权** | **必须另行确认覆盖**，并在 `src/static/ASSETS.md` 登记来源与范围 | R688 只覆盖 CardGame 那套（牌面/牌背/头像/UI/音效），**不含新图** |
| **换图方式** | 改 `src/uni.scss` **一行**：`$ftl-art-x: none;` → `$ftl-art-x: url('/static/ui/x.png');` | **布局一行不改** —— 这就是 R733 的「开发期换素材」 |
| **引用形态** | `/static/ui/<文件>`（绝对路径） | `static/` 不走 Vite 的 asset 管线（不哈希、不内联） |

> ⚠️ **一条别踩的坑**：`uni.scss` 里**既有**那批 `$ftl-btn-plate` / `$ftl-panel-slice` 存的是**路径**，
> 而 `$ftl-art-*` 这批**连 `url()` 一起存**。差别不是笔误 —— `url(none)` 是**非法值**，
> 整条声明会被**静默丢弃**（不报错、单测也看不见）。加新槽时照 `$ftl-art-*` 的写法。

### 各槽的美术要点

- **① 地主徽章**：参考图是**竖向**的（高 > 宽），我方容器偏宽（56×35.2）。
  **以容器为准做成横向也能用**；若坚持竖向，我会同步改样式（一条 `width`）。
- **② 张数徽章底**：圆角矩形，**中空**（数字由 DOM 画在正中）。这是几个槽里与参考图
  尺寸最吻合的一个 —— 参考图 39.3×52.4 vs 我方 **48.2×52**（实测）。
- **③ 货币图标**：正方形即可，我方按正方形渲染（`background-size: 100% 100%`）。
  **已接通 `dou.png`**（金色「豆」形、51×51）—— 与参考图的「圆币」形状**不完全一样**，
  但它是库里对得上这个槽的现成素材（B6 裁决：先接通、观感由截图走查）。
- **④ 头像环**：**关键是中间透明**。我方用 `border-radius: pill` 裁，所以圆环的四角可以留白。
- **⑤ 倍数徽章**：我方容器**比参考图高**（57.2 vs 28.3），因为数字与「倍」字是**竖排**的。
  参考图是**横排**（`3倍` 一行）。若要完全照参考图，我改样式（把两行并一行）。
- **⑥ 倒计时钟**：整节见 **§3**（尺寸 88×92 / 我这档 56×56 / 中央钟 88×92；**素材未接通** ——
  库里的 `jishianniudi.png` 形状不匹配、被用户裁决不接；交付要求**不变**）。
- **⑦ 底栏底纹**：容器 **310.4 × 61**（实测；宽度随内容变，上限是底栏可用宽 1294）⇒ **只能九宫格**，
  拉伸会毁掉圆角与描边。范式照 `Panel.vue` 的 `$ftl-panel-slice`（源图 126×126、圆角 ~24px、
  切片宽 24——注意这个 24 是**源图像素**，与渲染尺寸是**两个量**，改一个不改另一个会切坏圆角）。
- **⑧ 结算绶带**：**已接通 `jujsidai.png`**（B5）—— 素材**只做底**，文字（「结算」）仍由 DOM 画。
  **已改 9-slice**（2026-09-29 用户裁决：整图拉伸会把两端卷曲翼横向压扁）。
  **交付/改图必须保持九宫格可切**（切片与渲染尺寸见下，来自源图的**结构边界实测**）：

  | 量 | 值 | 来源 |

  | 切片（**源图像素**，`border-image` 简写里的无单位四值，上/右/下/左） | **36 225 27 221** | 逐一量自 `jujsidai.png`（666×115）：上 36 = 拱顶落到满宽处；右 225 / 左 221 = 拱顶**平段**（x 221..440）的起止；下 27 = 中央带底沿 |
  | 渲染尺寸（px，`border-width`） | 上 16 · 右 **98**（令牌 `$ftl-ribbon-slice-x`）· 下 12 · 左 **98** | 源图像素 × 统一缩放 **0.444**（选定值：源图整图高 115 → 51 = 改 9-slice 前的盒高）。四角与上下边按它渲染；**中段（拱顶平段 + 带身）随文字宽度拉伸** |
  | 容器（渲染后实测，2026-09-29 B6-fix，真 chromium） | **324 × 79** | 宽 = 98+98+「结算」+ 两侧 padding；高 = 16+12+标题行高+上下 padding（中段拉伸的结果）。B6 曾测 128 × 51 = 改 9-slice **前**的旧形态 |
  | **中段的纵向缩放**（B6 评审 Minor 2 补记，2026-09-29） | **≈ 0.98**（= 51 ÷ 源图中段 52） | 中段（拱顶平段 + 带身）的高**由内容决定**：`padding 4 + 标题行高 43 + padding 4` = 51；而源图中段 = 115 − 36 − 27 = 52。⚠️ 与四角的 **0.444** 不是同一个数 ⇒ **头带与两翼上段相对源图被纵向放大 ~2.2 倍**（0.98 ÷ 0.444）——**设计如此，不是 bug** |

  三个数**互相牵动** —— 改 `border-width` / 令牌 / 字号 / 上下 padding 任一个，另外两个的**观感**就跟着变。
  ⇒ 新素材必须在「拱顶平段纵向被拉到 0.98」的前提下仍不变形（`Settlement.vue` 的 9-slice 注释逐字记着这条）。

## 2.1 页面底纹（**不属于 `$ftl-art-*` 槽，但同样「有名字、有分辨率、一行可换」**）

> **登记理由**（用户 2026-09-29）：「记住元素的名称和分辨率，以后有实际美术素材**直接能替换**就行了」。
> 底纹是**全屏**的，规格与槽位不同（不是装饰件），所以单独列在这里 —— 但**替换方式同样是「一行」**
> （指换**已在用**的键那张图；启用一个**生产未接线**的键不止一行 —— 见本节末尾的订正）。

| 项 | 定 |
|---|---|
| **元素名 / 机制** | `LandscapeStage.vue` 的 **`BACKDROPS` 映射表**，键 = `'default'`（四页缺省）· `'table'`（牌桌专用） |
| **页面怎么声明** | 页面给舞台传 **`backdrop` prop**（`<LandscapeStage backdrop="table">`）；缺省 `'default'`。⚠️ **不传 = 用 default**，页面**不得**自己铺底纹（两层会因缩放比不同而**错位**，R713） |
| **目标分辨率** | 画布 **1334×750** ⇒ 交付 **2668×1500**（照本文件总则的 **2×**）。⚠️ 底纹走 `background-size: cover` ⇒ **纹理类**素材比**具象场景**更合适（具象图会被裁） |
| **现用素材（占位）** | `bg.png` **960×640**（`default`，四页在用的那张）· `Common_BG4_2x.png` **1024×1024**（`table` 键，**已登记但 2026-09-29 裁决不启用** —— 它在 1334×750 上 `cover` 会**纵向裁掉近一半**，海滩落在被裁的部分） |
| **怎么换** | 改 `BACKDROPS` 映射表里**已在用的那个键**的图路径（一行），**布局一行不改**；换名字要同步 `landscape-canvas.test.ts` 的 R713 判据（它断言「铺底纹的写法只允许出现在 `LandscapeStage.vue`」+「映射表里每张图都在盘上」）。⚠️ 前提：该键**已被某个页面接线**（`default` 是；`table` 不是 —— 见下行） |

⚠️ **§5.4 的裁决（2026-09-29）**：看过并排图后**维持 `bg.png`**。
机制已建好、`table` 键与那张图都已登记。⚠️ **订正（2026-09-29 评审）**：启用 `table` 底纹**不是「换一行」**

（`<LandscapeStage backdrop="table">`）。**当前四个页面都是裸 `<LandscapeStage>`、`table` 键在生产零调用点**
