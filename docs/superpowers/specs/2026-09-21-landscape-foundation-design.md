| **R722** | **`ui-tokens` 的判据也要一起反转**（规则 + 自证 + 正反对照，**三件一起改**）—— 详见 §3.2.1 的清单 | **修正设计初稿（漏项）** |
| **R723** | 本片**逐条沿用**既有全局约束（§1.4），其中与单位体系有关的那条按 R711 改写 | 结构性补齐 |

> **R717 的来由**：用户原话是「货币位先用数字填充展示」。这撞上上一片 UI spec §1-7 的逐字硬边界
> ——「**不得以「更好看」为由新增展示字段**」。`PlayerView` 无货币字段 ⇒ 填数字只能是编的，
> 而**看的人会以为它通了**（本仓为「看起来有数据、其实是假的」付过多次代价）。
> 权衡后用户选定：**版式照常占位、三座位统一 `—`** —— 版式效果看得出，且一眼可知「还没接」。
>
> **R719 的来由**：用户原话是「局内要展示倍数」。**能显示**与**能算**是两件事：
> `bidPhase.bidMultiplier` 是服务端下发的**数字本身**（原样展示，合法）；
> 而参考图里的 180 是多个因子的**乘积**，协议里没有任何一个字段是它 ⇒ 前端乘出来就是自算倍数。
> ⇒ 本片与片② 都只显示 `bidMultiplier` **原值**。

### 1.1 设计初稿的自审（写进规格，作为「本片有哪些坑」的清单）

本规格由设计对话产出，**起草过程中自审出 8 条问题**，逐条已修进下文：

| # | 设计初稿的问题 | 处置 |
|---|---|---|
| 1 | 判据「`k×1334 ≤ 视口宽` 且 `k×750 ≤ 视口高`」是**恒真式**（`k ≡ min(…)` ⇒ 按定义必然成立）—— **零判别力**，会伪装成「已验证」 | 删除；换成「**极端宽高比下的可用性**」判据（§5.2） |
| 2 | **12 条 `1px` 发丝线**在 `k≈0.52` 下缩到 `0.52px` ⇒ 按闸里白名单自己的理由「多端在 1px 以下会渲染不出来」，会**直接消失** | 新增 `$ftl-hairline: 2px`（R714） |
| 3 | 底纹可能被叠**两层**且缩放比不同 ⇒ **错位** | 只铺一层（R713） |
| 4 | `k` 是 JS 算的 ⇒ 首帧以 `scale(1)` 渲染，**先闪一下巨大溢出** | ~~初始 `visibility: hidden`，算完才显示~~ → **该修法在第三轮被推翻**（它带来永久白屏风险，见回核 #13）。最终改为**同步算**：`k` 在 `setup()` 里算出来，**取消隐藏这一相**（§2.3） |
| 5 | 「旧竖屏页面冻结保留」**缺理由**，且让两套单位体系长期共存 | 改为**删除**（R715） |
| 6 | 既有 `rpx` 令牌与 **F1 算账判据**的命运没写 | 补 §3.3 |
| 7 | 画布 `1334×750` **缺理由**（「同比例才能 1:1 誊写」对任何 16:9 尺寸都成立，不是选 1334 的理由） | 补 §2.1 |
| 8 | 参考图尺寸是**我编的** | 订正为实测 1936×1087（§0.1） |

自审中**排除**的风险（实测）：全仓 **`position: fixed` 零使用** ⇒ `transform: scale` 不会破坏 fixed 定位。
自审中**承认**的固有代价：`k` 通常非整数 ⇒ 缩放下文字**次像素发虚**（§7-3）。

### 1.4 全局约束（**不许破的既有纪律**，适用于本片每一个 Task）

> 回核 #21：设计初稿缺这一段。本仓其它 spec 都带它，而它正是**实施计划里 Global Constraints 的真源**
> —— 缺了它，计划就得自己发明一份，那正是本仓「清单会漏」的老路。
> 本节逐条沿用既有口径，**只把与单位体系有关的那条按 R711 改写**。

1. **范围 = H5 + App**（R701）。小程序端排除在**一切设计/开发/测试**之外：不删代码、不做适配、不入任何门禁、不为它写用例。
   ⚠️ 本片**会连带改变 mp 构建的输入**（同一份源码、单位体系换 px）⇒ mp 可能跟着坏，**而它不被任何门禁覆盖** —— 这是 R701 已接受的代价，不在本片修复。
2. **锚点零改动**：9 个探针 class 一个不改；**`scripts/browser-e2e.mjs` 本片零改动**（首次改动在片③）。
3. **判据只增不减**：8 个契约测试的字面 `it(`/`it.each(` 计数基线 **65**（63 + 2），逐文件核对。
4. **样式只用令牌**（`src/uni.scss` 的 `$ftl-*`）。⚠️ **本片起单位是 `px`（R711）**；发丝线一律 `$ftl-hairline`（R714）。
5. **`uni.xxx()` 必须是直接成员调用**（闸：`uni-api-access`）；**不得用 `document` / `window` / `fetch`**（本片的窗口变化监听因此只能走 `uni.onWindowResize`，见 §2.3）；不得 `typeof import.meta`。
6. **scoped 样式只到子组件根节点**：抽进子组件的元素**必须自持样式**（闸：`table-bid-bottom` 的「渲染 `class="btn"` 的组件必须自己 `@include ftl-btn`」）。
   ⚠️ **本片抽 `LandscapeStage.vue` 时是高发点**。
7. **模板注释只能放单根元素内部**（放根前 ⇒ 组件变多根、`classes()` 静默返回 `[]`）。
   ⚠️ **本片给三页套 `<LandscapeStage>` 时是高发点**（上一片我就踩过，由既有单根闸当场抓住）。
8. **`mount()` 看不见样式**（jsdom 不注入 CSS）⇒ 观感类改动只能用**产物 CSS / 真浏览器 / App 走查**证明，**不要造假判据**。
9. **门禁口径**：`turbo run build --force` 对 client **只出 h5** ⇒ App 必须 `pnpm --filter @fight-the-landlord/client build:app` 单独跑（R669）；探针**独占**跑（`kill -TERM -<pgid>`，**禁止** `pkill -f vite`）。
10. **证据卫生（R682）**：门禁日志的 mtime 必须**晚于**最后一次改动/commit。
11. **提交**：每个 commit 末尾带 `Co-Authored-By: Claude Opus 4.8 (1M context) <noreply@anthropic.com>`。**禁止** `git stash` / `git reset` / `git checkout <旧 commit>`。

## 2. 尺寸与适配底座

### 2.1 唯一坐标系：设计画布 `1334 × 750 px`

**选 1334 的理由**（补 R710 的依据）：

- 与参考图 **同比例**（16:9）⇒ 参考布局可 1:1 誊写，不做二次换算；
- **1px 粒度足够细**：1334 宽下，一个 100px 的组件仍能表达 1% 级别的微调；
- **数值好算**：16:9 的边长关系使 `× 0.75` / `÷ 4 × 3` 这类口算在评审时当场做得出来。

⚠️ **明记取舍**：现代手机多为 **19.5:9**，16:9 画布在其上**左右各留约 86px**（以 866×390 计，约 10% 屏宽）。
用户裁决 **R710** 接受此代价，换来「布局可算术证明」。**留边由底纹填满**（R713），不是黑边。

### 2.2 缩放：整页等比 + 黑边填充

```
┌─ .stage   position: fixed; inset: 0; padding: 安全区          ← 唯一一层底纹
│           background = new_BJ.png / cover（留边区域也显示底纹）
│   ┌─ .canvas  1334×750，在**安全框内**居中，transform: scale(k) ─┐
│   │              真正的 UI 全在这一层                            │
│   └────────────────────────────────────────────────────────────────┘
└──────────────────────────────────────────────────────────────────────┘
```

**`.stage` 的定位写死 `position: fixed; inset: 0`**（回核 #14）：不依赖祖先链的高度。
H5 侧有 `#app, uni-app, uni-page, uni-page-wrapper { height: 100% }`（产物 CSS 实测），
但 **App 侧的祖先链未知** ⇒ 用 `fixed` 把这件事变成确定的。

⚠️ `position: fixed` 在这里**安全**（回核 #22 实测）：
- 被 `transform` 捕获的是 fixed 的**祖先链** —— `.stage` 自身没有 transform，而 `.canvas` 的后代经实测**零 fixed**（§1.1）；
- 页面壳是 `uni-page-wrapper { position: relative }`（产物 CSS 实测）—— **`relative` 不捕获 fixed**（只有 `transform` / `filter` / `perspective` / `contain` 会）。
  ⇒ 这是本设计**唯一**依赖 fixed 的地方，也是它成立的两个实测前提。

**整页不滚动**（回核 #23）：`.stage` 铺满视口且画布恒为一屏 ⇒ **页面不得出现滚动**。
`.stage` 自带 `overflow: hidden`（正常模式与失败模式**都要**，不是只在失败时才加）。

**画布在安全框内居中**（回核 #12）：`.stage` 用 `padding` 吃掉安全区，`.canvas` 在**剩下的盒子**里居中。
不这么做的话，横屏常见的**不对称**安全区（刘海在一侧：`left 44 / right 0`）会让画布在全视口居中时
两边各让 `(44+0)/2 = 22px < 44px` ⇒ **画布左边压进刘海**。

### 2.3 缩放比由 JS 纯函数计算（R712）

```ts
export const CANVAS_W = 1334;
export const CANVAS_H = 750;
export interface Insets { top: number; right: number; bottom: number; left: number }

/** 画布缩放比。`insets` 为安全区（刘海/挖孔），缺省 0。 */
export function landscapeScale(w: number, h: number, insets?: Partial<Insets>): number

/** 是否竖屏（H5 用；App 锁横屏后不会为真）。 */
export function isPortrait(w: number, h: number): boolean
```

**为什么用 JS 而不是 CSS `min()` + `vw/vh`**：
- `ui-tokens` 闸**禁用 `vw`/`vh`** ⇒ 用 CSS 方案要再开一次白名单，而 JS 方案**一个字都不用改闸**；
- App 端不依赖 CSS 单位的支持程度（App 是 webview，但窗口尺寸事件与安全区在两端行为不同，JS 里统一处理更稳）；
- **纯函数可单测** —— 这是本片唯一能对「适配」这件事做机械验证的手段（无设备实验室）。

**首帧（FOUC）—— 用「同步算」让它根本不发生**（回核 #13 的修法）

设计初稿写的是「初始 `visibility: hidden`，JS 算完 `k` 再显示」。回核时发现它有个白屏风险：
**JS 一旦失败，页面永久不可见** —— 与本仓两条既有纪律冲突（R693「素材缺失要兜底、不白屏」、
`animations.scss` 逐字写的「**起始态必须可见** —— 动画不执行时元素不能永久隐形」）。

**修法不是加兜底，是把隐藏这一相取消掉**：`uni.getSystemInfoSync()` 是**同步**的
⇒ **`k` 在 `setup()` 里同步算出来**，**首帧就是对的** ⇒ 不需要隐藏、不需要定时器、不会有 FOUC。

> ⚠️ 顺带否掉了一条候选修法：**「超时兜底」（N 毫秒后无条件显示）不能用** ——
> `animations.test.ts` 扫 `src/components/**` 的 `setTimeout`/`setInterval`（牌桌区「不新造时钟」纪律），
> `LandscapeStage.vue` 正在那个扫描面里。**是既有的闸替我们选了实现**。

**窗口变化时必须重算**（回核 #20）：`k` 只在 `setup()` 算一次是**不够**的 ——
H5 上浏览器窗口是**可变的**（拖拽、devtools 设备模拟、手机旋转），窗口一变画布就该重算，
而"不重算"的表现是**布局错但不报错**。

```
uni.onWindowResize(handler)    // 挂载时注册
uni.offWindowResize(handler)   // 卸载时注销（不注销 = 泄漏 + 卸载后仍回调）
```

⚠️ **只能用这个 API**：本仓**禁 `document` / `window`**（§1.4-5），`window.addEventListener` 走不通。
✅ **实测可用**：`onWindowResize` / `offWindowResize` / `getWindowInfo` **都在 `@dcloudio/uni-h5` 的导出名录里**
（与 `createInnerAudioContext` 同一类验证方式）。

**失败模式（必须有，且不依赖成功路径）**：`getSystemInfoSync()` 放 `try/catch`；
捕获时用 `k = 0.5`（手机上一定放得下的保守值）+ `.stage { overflow: hidden }`
（`overflow: hidden` 正常模式也常驻，见 §2.2）—— **内容可能被裁，但不会白屏**。

**判据**：源码级断言 `k` 的初值来自 `setup()` 的**同步**计算（不是异步回调里赋值）；
`getSystemInfoSync()` 的调用点被 `try/catch` 包住；且**挂载/卸载成对出现** `onWindowResize` / `offWindowResize`。

**安全区**：`insets` 优先取 `uni.getSystemInfoSync().safeArea`；取不到则**回落全 0**
（回落时行为等同「无安全区」，**不崩**）。
> ⚠️ **未验事项（诚实登记）**：`@dcloudio/types` 里未直接命中 `getSystemInfoSync().safeArea`；
> uni-h5 侧存在 `safeAreaInsets` 模块（实测）。**实现时按 `lint` 与真浏览器走查定**；
> 若该字段不可用，回落方案是 CSS `env(safe-area-inset-*)`（`env()` 不含被禁单位，闸能过）。

## 3. 单位体系：`rpx` → `px`（R711）

### 3.1 为什么必须换（实测数据）

uni-app H5 的 rpx 换算（`uni-h5.es.js:731-738`，读源码）：

```js
let width = 视口宽;
width = width <= 960 ? width : 375;                        // 超过 960 就回落 375 基准
documentElement.style.fontSize = width / 23.4375 + "px";   // 等效 1rpx = width / 750
```

| 场景 | 视口宽 | `1rpx` = | 后果 |
|---|---|---|---|
| 现状（手机竖屏） | 375 | 0.5px | 现状基准 |
| **手机横屏** | 866 | **1.155px** | 所有 rpx 尺寸**放大 2.3 倍** |
| 平板 / 桌面 | 1280 | **0.5px**（回落 375 基准） | 反而缩回手机大小，铺不满 |

**rpx 存在的全部理由就是「跨屏宽自适应」—— 而画布 + 等比缩放已经把这件事做掉了，且做得更确定。**
有了固定画布，`px`（设计像素）才是正确单位。

### 3.2 闸的翻转（本片唯一一次翻闸）

| | 现在 | 改为 |
|---|---|---|
| `ui-tokens` 的单位规则 | **禁 px**（只许 rpx），理由是「尺寸单位一律 rpx（750rpx = 屏宽）」 | **禁 rpx**（尺寸一律 px），理由是「画布是固定坐标系，px = 设计像素」 |
| 发丝线白名单 `border: 1px solid …` | 允许 | **撤掉**。全仓发丝线一律用 `$ftl-hairline`（2px）；`0px` 那条白名单保留 |

⚠️ **为什么撤白名单而不是「画布内另立规则」**：写「画布文件里禁裸 `1px`」会立刻引出一个没法机械判定的问题
—— **哪些文件算「画布文件」**？靠人工维护清单，必然腐烂（本仓为「清单会漏」付过代价）。
**全仓禁**则没有这个歧义，且实施上等价（三页全部进画布，没有留在画布外的页面）。

⚠️ **这是一次闸的翻转，必须带理由登记**（本仓的白名单传统）。理由即 §3.1。

**澄清一（回核 #17）：px 是「尺寸单位」，不是「排布方式」**
「尺寸一律 px」管的是**宽高 / 字号 / 间距 / 圆角 / 描边**这些**长度量**。
**排布仍用 `flex` / `%` / `order` 等**（本仓现在就是 flex 布局，一行不改）。
⇒ 别把它读成「不能再用 flex」—— 那会让这套设计自相矛盾（固定画布**恰恰**需要一个确定的内部排布体系）。

**澄清二（回核 #16）：`uni.scss` 里那 2 条 `1px` 要点名**
其中一条是 **`ftl-btn` mixin 的 `border: 1px solid $ftl-color-border-control`** ——
它是**所有按钮的边框来源**（每个 `@include ftl-btn` 的组件都吃它）。
⇒ 改 `$ftl-hairline` 时**先改 mixin**，影响面就是全部按钮；实施时不能只扫 `.vue` 而漏了 `uni.scss`。

### 3.2.1 🔴 判据反转清单（回核 #19 —— **改规则必须同时改判据**）

**spec 初稿只写了「闸的规则翻转」，漏了「闸的判据自己也要反转」。**
`ui-tokens.test.ts` 里有 **5 处断言逐字编码了旧世界**，不改就红 ——
而**更危险的是**：如果为了变绿去删它们，闸就失去自证，变成「永远扫到 0 条也绿」的假绿。

| 位置 | 现在（旧世界） | 翻转后应为 |
|---|---|---|
| 自证 ① | `expect((text.match(/\dpx\b/g) ?? []).length).toBeGreaterThanOrEqual(3)` | 断言 `\dpx` 计数 **=== 0** |
| 自证 ② | `expect(text, 'rpx 才是距离量的主体').toMatch(/\d+rpx/)` | 断言 `\d+rpx` **零命中**；**并新增**「px 才是主体」的正向自证（`\d+px` 计数 ≥ N）—— **否则新闸会变成「零命中恒绿」** |
| 正对照 ① | `expect(pxOffenders('.card { border: 1px solid #c8c8c8; }')).toEqual([])` | `toHaveLength(1)`（1px 现在是违规） |
| 正对照 ② | `expect(pxOffenders('.card { border: 1px dashed #e0e0e0; }')).toEqual([])` | `toHaveLength(1)` |
| 白名单 `0px` | `pxOffenders('.card { margin: 0px; }')).toEqual([])` | **保留**（`0px` 那条白名单不撤） |

⚠️ **`PX_WHITELIST` 里那条 `border: 1px solid` 要删掉**（R714），`0px` 那条留。
⇒ 实施时这是一处**必须成对做的改动**：**改规则 + 改自证 + 改正反对照**，三件一起。

> **本条的普适形态**（值得记进方法论）：一个闸有**两层** ——「规则」（它拦什么）与
> 「判据」（它怎么证明自己真的在拦）。改规则时只改规则 = 判据失效。
> 本仓反复说的「判据存在 ≠ 判据有效」，这次是以**「改了规则、没改判据」**的形态出现的。

### 3.3 待改令牌与连带判据（**实测规模**）

**33 个尺寸令牌**（扫 `uni.scss`，值为 `rpx` 的行）：

| 类别 | 个数 |
|---|---|
| `space` | 9 |
| `font` | 9 |
| `card` | 6 |
| `radius` | 4 |
| `control` | 2 |
| `size` | 2 |
| `panel` | 1 |
| **合计** | **33** |

> ⚠️ **这个数被订正过**（回核 #10）。设计初稿写「24 个」并给出 `card 9 / font 6` ——
> 两个都错。24 来自一条**坏正则**：`^\$ftl-[a-z-]+:` 里的 `[a-z-]` **不含数字**，
> 于是漏掉了名字带数字的令牌（`$ftl-space-2` … `$ftl-space-10` 等）；
> 而 `card` / `font` 的计数是**对调**写反的。
>
> **教训**：计数类主张的判据是**换一个写法再数一遍**，不是相信自己第一次的输出。
> 修复方式就是上面那条 `[a-z0-9-]+`（多一个 `0-9`，结果从 24 变 33）。

⚠️ **不是换算，是重新定** —— 画布 1334 宽**不是** 375 逻辑宽的等比放大，横屏的尺度关系变了。

⚠️ **连带一条既有判据的数字**：`apps/client/test/card-hand-interaction.test.ts` 的 **F1 算账**
（「牌框比例贴住真牌」「20 张单行放得下」「净露率在档位区间」）读的是令牌**真值**（从 `uni.scss` 现读）
⇒ 令牌换 px 后**判据本身不用改**，但「**可用宽 710**」这个阈值**要按新布局重算**（画布宽 − 两侧内边距）。

## 8. 执行期发现

> 片① 实施（2026-09-21，8 个提交）中实测出来的。格式：**现象 → 根因 → 被什么抓住 → 修法**。
> ★ 标记的是**改变了设计本身**的发现。

### ★ F1 · 基准缩放 S=2 是错的 —— 实测抓出，改成 S=1

**现象**：Task 2 把令牌 ×2 之后，Task 4 的登录页横屏骨架在**真浏览器**里量出来：登录卡片
**2444 设计 px 高**，而画布只有 **750** ⇒ 被 `overflow: hidden` 裁掉。

**根因**：×2 的理由写的是「画布高 750 ≈ 旧坐标系 375 的 **2 倍**」——**把宽和高搞混了**。
旧设计是 375 **宽**的竖屏；画布 1334×750 是**横**的。纵向预算是 750，而旧内容在竖屏里
用了 812 逻辑 px（且是**滚动**的）。

**两个约束无解**（写规格时没算这笔账）：

| 约束 | 需要的 S |
|---|---|
| 登录页纵向装进 750（两列排布后最高列 ≈1400） | **S ≤ 1.07** |
| 手牌行铺满画布宽 85%（参考图的形态，系数 9.44×牌宽） | **S ≈ 1.67** |

⇒ **相差 2.7 倍，单一均匀缩放因子无解。**

**修法**：基准取「最紧的那个」（表单）**S=1**；**牌面尺寸留给片② 单独放大**（只影响牌桌）。
S=1 的物理依据：旧 rpx 在参考设备（375 逻辑宽）上是 0.5 逻辑 px，而 S=1 时 1 设计 px
在手机横屏（866×390，k=0.52）上是 **0.52 ≈ 0.5** ✅ 一致（×2 会得到 1.04，是参考设备的两倍）。

**教训**：**「等比缩放」不能只按一个维度算**。这条是**真浏览器测量**抓出来的 ——
单测与产物 CSS 都看不见（jsdom 不布局）。

### F2 · 闸的「判据反转清单」本身不全

**现象**：规格 §3.2.1 列了 **5 处**（都在 `ui-tokens`）要反转的判据。实施下来实际是
**3 个文件 / 11 处功能性判据**：
- `ui-tokens`：自证 2 + 正对照 2 + **token 阶的 3 条正则**（规格与我的第一遍都漏了后 3 条）
- `card-hand-interaction.test.ts` 的 **U1 算账 `token()`**（用 `\d+rpx` 正则解析令牌真值）
- `table-seat-geometry.test.ts` 的 **§6.5-1 `fontRpx()`**（连变量名都该改）

**根因**：清单是**按文件**列的，而这类判据的**共同特征**是「用 `\d+rpx` 正则**解析令牌值**」
—— 它散在任何读令牌的测试里。

**修法**：条目化的清单换成**特征化的搜索**：`grep -rn "rpx" apps/client/test/`（排除注释）。

### F3 · 包裹 `<LandscapeStage>` 改变了**页面根**

**现象**：`table-hud.test.ts` 的单根闸红了：`expected [ 'stage' ] to include 'login'`。

**根因**：三页套画布之后，**组件根变成 `.stage`**，页面自己的根 class 下沉一层 —— 原断言
「`wrapper.classes()` 含页面自己的根 class」**必然为假**。

**修法**：**迁移而非删除**（它防的东西没消失：fragment root 仍会让 `classes()` 为 `[]`），
且迁移后**更强**：既钉「根是 `.stage`」，又钉「页面自己的根 class 仍在」。
⚠️ 连带：`table.vue` **不能裸挂载**（setup 里就要 game session）⇒ 它单独留在 `mountTable` 那条路径。

### F4 · 我写的注释破了**我同一提交里写的闸**

**现象**：底纹唯一性判据红了，命中 `src/pages/table/table.vue` —— 而那里的 `new_BJ.png`
只出现在**我新写的注释**里（解释「底纹不在这里」）。

**根因**：违规类断言读的是**原始文本**。本仓的既有口径（R572/R622）是**读剥注释视图**。

**修法**：判据改读 `stripComments` ✅（与 `source-boundary` 等闸同口径）。

### F5 · 假回归：残留的 vite 占着 5173

**现象**：Task 3 改完第一次跑探针**大面积失败**（注册都过不去），看着像画布把页面搞坏了。

**根因**：`pnpm dev:h5 &` 之后 `kill -TERM $!` 只杀了 **pnpm 包装**，**vite 子进程活着占着 5173**
（探针自己的注释早记过这个坑）。我的诊断脚本打到了那个旧 server 上；而新起的 server
因端口占用退到了 **5174**，日志里那句 `Port 5173 is in use, trying another one...` 就是线索。

**修法**：收尾**按 PID 杀整棵树**（`taskkill //F //PID <5173 的 PID> //T`），不杀 pnpm 包装。
改完重跑：**16/16** ✅ —— 改动本身没问题。

### F6 · 机械改动**漏提交了 4 个文件**

**现象**：S=1 订正提交之后，`git status` 还留着 `Card.vue` / `animations.scss` / `lobby.vue` / `table.vue`
（同样被减半的文件）。

**⚠️ 为什么值得记**：**没有任何闸会抓到「少提交几个文件」** —— 单测看不见 CSS 值、探针只数元素个数。
「改了一半」会以「看起来已订正」的形态留在工作区里。

**修法**：机械改动的提交必须**核对 `git status` 全量**（已单独补一个 commit）。

### F7 · 幽灵按钮换行：**差 2px**

**现象**：登录页右列的「以开发身份进入（连 mock 用）」实测高 **168px**（应为 56）—— 换成了两行。

**根因**：文案 17 个字符（含全角括号）在 `$ftl-font-sm`(26) 下需要约 400px；而 `ftl-btn` mixin
的内边距 `0 $ftl-space-8`(24×2) 把列宽 384 压到 **336** ⇒ 换行。降到 `$ftl-font-sm` 后仍需 338
⇒ **差 2px**。改成 `0 $ftl-space-6`(16×2) ⇒ 内容宽 352 ✅ 单行（70 高）。

### F8 · `px` **不被 uni 改写**（rpx 会被转成 `rem`）

**实测**：产物 CSS 里 `.card` 是 `width:144px`（字面 px），而 S=2 时同一处是 `2.25rem`。
⇒ `rpx` 由 uni 编译成 `rem`（跟视口走），而 **`px` 原样保留** —— 这正是固定画布要的
（画布内必须是**不随视口变化**的绝对单位）。

**意义**：这条从产物侧**证实了 R711 的单位选择的正确性**，而不只是"我们决定这么做"。

### F9 · 三区几何**没量到**（诚实登记）

Task 6 的三区（对手分左右）**没有**登录页/大厅那样的逐元素坐标实测：
我写的一次性测量脚本走不通撮合（大厅永久停在「正在匹配」，无 notice、无 console error；
**探针却能过** —— 差异未查明），`--keep-open` 又会让探针挂住。

**替代证据**（弱一档，但要如实说清是什么）：**产物 CSS 的结构证据** ——
`.table__mid{display:flex;flex-direction:row}` · `.table__seat{flex:0 0 300px}`（两个，位于两端）·
`.table__center{flex:1 1 0}`（居中）· 手牌重叠 `margin-left:-40px`。这足以证明**排布**，
**不足以**证明观感。

## 10. 风险与已知代价

> ⚠️ **本节写下时的数字有 3 处随执行期订正过期**（保留原文以便追溯，订正见 §8 F1）：
> 「24 个令牌」应为 **35 行**（两条阴影令牌是复合值，被单值正则漏掉）；
> 「把 rpx 值除以 2」—— 实际基准是 **S=1**（值 = 原 rpx 数），不是除以 2。

1. **闸的翻转（R711）是全仓级**：`ui-tokens` 从禁 px 变成禁 rpx，会一次性让**所有**含 rpx 的文件变红。
   处置：这是**有意的**——它就是「删除竖屏布局完整性」的机械判据。但实施时必须**逐文件清零**，不能靠白名单放行。
2. **24 个令牌是重新定值，不是换算**：任何「把 rpx 值除以 2」的做法都会得到一套错的尺寸。
   判据只有走查 + F1 那条算术。
3. **非整数缩放下文字次像素发虚**：`k` 通常非整数（866×390 ⇒ 0.52）。这是甲方案的**固有代价**。
   ⚠️ 若走查判定不可接受 ⇒ 只能回「全自适应」方案，而那要推翻 R710 并重写 §2/§3。
4. **极端宽高比下画布会缩得小**：3000×400 时 `k = min(2.25, 0.53) = 0.53` ⇒ 内容只占视口宽的约 24%，
   两侧全是底纹。已在 §5.2 立了可用性判据，但**阈值本身是人的取舍**。
5. **安全区字段未验**（§2.3 的未验事项）：`getSystemInfoSync().safeArea` 在 types 里未直接命中。
   取不到的回落是「无安全区」⇒ **刘海可能遮住画布边缘**（不崩，但难看）。
6. **`k` 仍然依赖 JS**：虽然改成 `setup()` 里**同步**算（消除了 FOUC 与隐藏相），但页面渲染仍晚于
   `getSystemInfoSync()` 返回。若它抛错或返回异常值，走 §2.3 的失败模式（`k=0.5` + `overflow: hidden`）
   —— **不白屏，但内容可能被裁**。
7. **片① 出片时观感仍不等于参考图**：本片只做骨架（R716），图1 的货币/底分/倍数条/座位精修在片②。
   ⚠️ **不要把「片① 完成」读成「UI 已经像欢乐斗地主了」。**
