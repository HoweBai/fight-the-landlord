## 1. 背景与目标

当前牌桌是 10-30 四家围桌布局（天月风回退后的基线）。用户对两次重做的结论都是「不美观」：

| 片 | 做了什么 | 结果 |
|---|---|---|
| 10-30 中央牌板 | 四道全高 + 信息格占满中间列 + 副露移出竖向预算 | 整片回退 `7c7e2424`，原因未说明 |
| 11-02 天月风 v1+v2 | 蓝青桌面/炭黑中央盘/冷白牌/亮蓝背 + 中央四家信息 | 整片回退 `7a235324`，用户判定仍不美观 |

本次目标不是再换一层皮，而是重做**信息骨架 + 动线**。用户已确认：

- 目标气质：**川麻红中血流式**（红金、喜庆、大字号、突出血战到底）。
- 最不满意：布局与信息层次、交互与动效（两项全选）。
- 布局骨架：**A 经典围桌 + 紧凑血战盘**。
- 座位牌：上家左上、下家右上、对家上中、自己左下。
- 信息层级、动效清单、样式 token、技术落点均已逐节确认。

## 2. 两次回退的教训（本片必须避开）

1. **不要用大面板解决信息问题**：中央信息格/大卡片会把牌桌变成仪表盘。本次中央只放一个紧凑血战盘（直径约 192），且只放四类信息。
2. **不要一次性整片重做再验收**：前两次都是全量实现后才发现方向不对。本次强制 **mockup 先行**：四档高保真静态图确认后才改代码。
3. **不要为了氛围牺牲可读性**：牌河不能缩小到看不清；信息不能在边缘重复三份。
4. **动效不是常驻装饰**：同一时刻只允许一个「大声」的元素。
5. **保留已合入的非视觉修复**：`wallEmptyWithHu` 协议/类型/校验、结算面板增强等，不在本片回退范围内。

## 4. 构图与分区（D1–D6）

画布仍按设计尺寸等比缩放，横屏。基准 1334×750，s = min(H/750, 0.88W/手牌行宽)，s ≥ 1。

### 4.1 分区

| 区域 | 位置 | 内容 |
|---|---|---|
| 顶部栏 | 0–64 | 左：房间/底分；右：托管/更多；中：对家座位牌 |
| 上家座位牌 | 左上角 | 头像 + 名字 + 分数 + 庄/缺/听/胡/托管徽标 |
| 下家座位牌 | 右上角 | 同上 |
| 对家座位牌 | 顶部栏中央 | 同上（横向紧凑） |
| 自己座位牌 | 左下角，手牌左侧 | 同上 |
| 血战盘 | 画布正中 | 牌墙数、倒计时环、当前方位、四家状态徽标 |
| 对家牌河/牌背/副露 | 血战盘上方 | 牌背在上，牌河在下，副露贴牌河外侧 |
| 上家/下家牌河/牌背/副露 | 血战盘左右 | 竖向排列，副露贴外侧 |
| 自己牌河/副露 | 血战盘下方、手牌上方 | 牌河在下，副露夹在牌河与手牌之间 |
| 手牌 | 底部居中 | 14 张，摸牌独立间隔 |
| 动作轨 | 手牌右侧 | 碰/杠/胡/过/出牌，最多 3 行 2 列 |

### 4.2 尺寸基线（1334×750，s=1）

| 元素 | 基线值 | 允许微调 |
|---|---|---|
| 顶部栏 | 64 | 固定 |
| 血战盘直径 | 192 | ±8 |
| 牌河牌高（上/下） | 56，2 行 | ±4 |
| 牌河牌（左/右） | 56×37（旋转），2 列 × 6–8 行 | ±4 |
| 手牌高 | 108 | ±4 |
| 摸牌间隔 | 12 | 固定 |
| 座位牌头像 | 56 | 固定 |
| 座位牌整体 | 128×56（左右/自己），144×56（对家） | ±8 |
| 动作按钮 | 56×56，2 列 × 最多 2 行（同屏最多 4 个动作） | 按钮 48–64 |
| 动作轨宽 | 128，右下角，右缘距画布 12 | ±8 |
| 桌面外框 | 12 | 固定 |
| 上家/下家牌背 | 竖向叠压，pitch 24；与对家牌河顶对齐，底缘 ≤ 手牌顶 − 动作轨高 − 2×inner | ±2 |
| 对家牌背 | 水平一排，高 46 | ±2 |

竖向预算（s=1）：64 顶栏 + 6 + 46 对家背 + 6 + 114 对家河 + 6 + 192 血战盘 + 6 + 114 自己河 + 6 + 36 自己副露 + 6 + 108 手牌 + 12 外框 = 722，余 28。

左右座位区与血战盘并行，不占上述竖向预算；其底缘必须让出右下角动作轨（动作轨 y ≈ 510–630，侧区底缘 ≤ 500）。

### 4.3 牌河规则

- 四条牌河围成十字，四家牌尺寸一致（同一基础牌尺寸按座位方向旋转）。
- 上/下河：8 列 × 2 行（容量 16）；超过 16 张扩到 3 行（容量 24），仍超出按现有 `fit` 压缩。
- 左/右河：2 列 × 6 行（容量 12）；超过 12 张扩到 2 列 × 8 行（容量 16），仍超出压缩。
- 每条河底靠桌心一侧有一条 `$ftl-hairline` 家色细线，标明归属。
- 最后一张弃牌金边 + 0.6s 脉冲；其余牌正常对比。
- 副露贴着各自牌河外侧：对家在上、左右在外、自己在河与手牌之间；副露组间距 8。

### 4.4 血战盘内容

只放四类信息，不显示分数：

1. 牌墙剩余（48px 等宽数字 + 「牌墙」16px 标签）。
2. 倒计时环（6px 金弧，按剩余秒数收缩；最后 5s 变红）。
3. 当前行动方位（东南西北四个小标记，点亮当前座位）。
4. 四家状态徽标（缺/听/胡/出局/托管），18px，挂在盘缘四个对角位；不写名字、不写分数。

听牌时，血战盘内下缘显示听牌行：最多 8 张 20×30 小牌 + 「听 N 张」，占用盘内下部，不额外占竖向预算。

### 4.5 手牌与动作轨

- 手牌 14 张居中，高 108；摸牌单独 12px 间隔；选中抬起 12px + 金边。
- 动作轨在手牌右侧外缘：宽 128，右下角，底部与手牌底对齐，最多 2 行 × 2 列 56px 按钮。出牌与碰/杠/胡/过不同时出现，同屏最多 4 个动作。
- 只显示当前可用动作；主按钮（出牌/胡）金色实心，次按钮（碰/杠/过）透明底金线。
- 倒计时环与当前行动提示并入动作轨上方，视线不离开手牌。
- 动作轨不得覆盖自家牌河或手牌；布局测试机械校验矩形不相交。

## 5. 信息层级与视觉权重（D7–D8）

**视线动线**：血战盘 → 自己手牌/动作区 → 自己牌河 → 座位牌 → 对手牌河/副露。

| 层级 | 内容 | 权重做法 |
|---|---|---|
| L1 | 血战盘 | 牌墙 48px；倒计时环 6px 金弧；当前方位点亮；状态徽标 18px |
| L2 | 自己手牌 | 108 高；摸牌独立；选中抬起 12px + 金边；不可出降饱和 |
| L3 | 动作区 | 主按钮金色实心 56–64；次按钮描金 48–56；只显示可用动作 |
| L4 | 自己牌河/副露 | 牌高 56；最后弃牌金边；副露组距 8 |
| L5 | 对手 | 头像 56、名字 18、分数 22、徽标 16；牌背/副露降对比 |

**去重规则**：

- 牌墙数只在血战盘出现，顶栏不再显示。
- 分数只在座位牌出现，血战盘不显示。
- 缺/听/胡只在本人座位牌 + 血战盘盘缘两处。
- 房间/底分只在顶栏。

**同一时刻只允许一个「大声」元素**：轮到我 = 动作区亮 + 倒计时环；可响应 = 动作按钮脉冲；胡牌/结算 = 胡字横幅；其余时间只有血战盘倒计时在动。

## 6. 动效与交互（D9–D13）

### 6.1 总原则

- 同一时刻只有一个主运动，其余反馈 ≤ 0.2s。
- 时长阶梯：点按 100–120ms / 出牌·碰杠 220–260ms / 发牌 360ms / 胡牌 600–900ms。
- 全部从可见态起手（不用 `opacity: 0`），只动 `transform` / `box-shadow`。
- 错峰用 CSS 变量，不新增 JS 定时器；动画不阻塞操作。
- 输入模型保持现状：单击选中、400ms 内再点同一张直接出、或点「出牌」按钮；不加拖拽。

### 6.2 事件表

| 事件 | 动效 | 音效/震动 |
|---|---|---|
| 发牌 | 洗牌 0.2s → 牌从血战盘四向飞出 0.36s、错峰 30ms → 手牌从左到右落位（复用 `ftl-deal-in`） | MjShuffle + MjDeal；轻震 |
| 摸牌 | 新牌滑入摸牌位、抬 8px + 金边光晕 0.18s；手牌重排 0.2s | MjSort；无震动 |
| 选牌 | 抬起 12px + 金边 + 阴影 0.1s；再点取消 | MjSort 轻点；轻震 |
| 出牌 | 本地先飞（现有 `anim-fly-out`）0.24s → 落河 2px 回弹；手牌合拢 0.2s；最后一张弃牌金边 + 0.6s 脉冲 | MjDeal 轻咔；轻震 |
| 碰/杠/胡提示 | 动作按钮自底部滑入 0.16s + 呼吸脉冲；可响应弃牌金圈；相关手牌描金 | 提示音（复用现有） |
| 碰/杠确认 | 牌从手牌/牌河飞向副露条 0.22s；副露 pop（复用 `ftl-peng-pop` / `ftl-gang-pop`） | MjPeng / MjGang；中震 |
| 过 | 按钮 0.16s 收起，无额外特效 | 无 |
| 回合切换 | 当前座位牌整块发光 1.2s 循环；血战盘方位点亮 0.3s；轮到自己动作区亮 + 倒计时环 | 轮到自己：轻震 + 提示音 |
| 倒计时 | 金环随剩余时间收缩；最后 5s 变红 + 1.12 脉冲 | MjTimeup 一次 + 中震 |
| 胡牌 | 胡字横幅（复用 `ftl-hu-banner`）+ 血战盘金光扩散 + 亮牌翻转（`ftl-reveal-in`）；0.6s 停顿后结算面板入场 | MjHu；重震；胜负 BGM |
| 托管/超时 | 座位牌托管徽标 + 降对比；自己托管时动作区换成「托管中 + 倒计时」；自动出牌走同一套动效 | 无额外音效 |
| 结算 | 面板 0.24s 入场；四家分数行错峰 35ms；不加数字滚动（避免新定时器） | 赢/输音效 |

### 6.3 音效与降级

- 全部复用现有 `Mj_*.mp3`，不新增素材；BGM 在 `play` 阶段切 `Mj_bgFight` 的现有逻辑保留。
- 动画不执行时所有元素保持可见；低端机/关闭动效时只保留 0.1s 位移与高亮。

## 9. 实施顺序（mockup 先行）

0. **高保真静态 mockup**：用真牌面素材出 1334×750、1334×1000、1778×750、844×390 四档；用户确认后才改代码。产物存 `.superpowers/mahjong-redgold/`（gitignored）。
1. 布局纯函数 v2 + 视口矩阵/不相交测试（此步页面视觉暂不变）。
2. `MahjongHub` + 四角座位牌 + 四向牌河，接上新布局。
3. 手牌 + 动作轨整合。
4. 动效清单逐条落地（含音效/震动）。
5. 四档截图/录屏 + 真机走查 → 部署测试服。

每一步一个提交；测试随步更新；第 0 步不通过不进入第 1 步。

## 10. 测试与验收（D20）

### 10.1 自动测试

- 布局矩阵：1334×750、1334×1000、1778×750、844×390。
- 状态矩阵：0/16/17/24/36 张弃牌；0/12/13/16 张侧河；0/4 副露；0/8 听牌；末 5 秒。
- 不相交断言：血战盘 × 四条河/牌背/座位牌/手牌/动作轨；动作轨 × 手牌/牌河/座位牌。
- 边界断言：所有矩形在画布内；牌河在容量内不溢出；听牌行在盘下缘。
- 组件测试：Hub 内容（牌墙/倒计时/方位/徽标，无分数）、座位牌四变体、牌河四方向、动作轨只显示可用动作。
- 主题闸：麻将组件不写裸 hex；小字号只允许登记过的 token。
- 回归：现有 client 全量测试、`vue-tsc`、`uni build`。

### 10.2 视觉验收

- 四档截图与当前版本并排；每类事件至少一条真浏览器录屏或连拍。

### 10.3 验收判据

- 视觉：用户确认四档 mockup 与上线截图。

- 性能：无新增定时器；素材预算不变；build 体积不变。

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| 844×390 小横屏太挤 | 血战盘缩到 ≤160；侧河 2×4；次要标签隐藏；四档矩阵纳入测试 |
| 单家弃牌超过 24 张 | 沿用现有 `fit` 压缩 + 3 行扩展；补 36 张极端用例 |
| 动作轨盖住自家牌河 | 固定在手牌右侧预留带；不相交测试机械校验 |
| 750 高度下中央盘与对家牌河相撞 | 布局函数先算竖向预算；不足时缩盘/上移对家河 |
| 动效在低端 App 掉帧 | 只动 transform/box-shadow；不做大面积 blur/filter；保留降级 |
| 影响其它玩法 | token/类名 `mj-` 前缀；跑全量 client 测试 |

## 12. 回退

- 本片分步提交；任一步不满意可整步 revert，不影响其它玩法。
- 测试服部署后如需回滚：`bash scripts/deploy/rollback.sh <上一个 dev-tag>`。
- 本片不触碰协议/服务端，回退只涉及客户端展示层。

## 13. 决策表

| 编号 | 决策 | 理由 |
|---|---|---|
| D1 | 目标气质：川麻红中血流式（红金、大字、血战感） | 用户选定 |
| D2 | 布局骨架 A：经典围桌 + 紧凑血战盘 | 用户选定；比 B/C 更接近牌桌且中央有焦点 |
| D3 | 座位牌：上家左上、下家右上、对家上中、自己左下 | 避开左右牌河中腰；形成画框 |
| D4 | 血战盘只放牌墙/倒计时/方位/状态，不放分数、不做信息格 | 避开 10-30 回退的中央面板形态 |
| D5 | 四条牌河围成十字，四家牌尺寸一致 | 解决牌河散落与归属不清 |
| D6 | 手牌 108 高；动作轨在手牌右侧 | 保持现有手牌素材比例；动作不盖牌河 |
| D7 | 五级信息权重 + 去重规则 | 建立单一视线动线 |
