### 3.2 ⚠️ HBuilderX 的真实角色：**打包器，不是开发环境**

这条本会话专门纠正过，**别在新会话里说反**：

- 今天的流程（手册 §9）：`pnpm --filter @fight-the-landlord/client build:app` ⇒ 产出 `dist/build/app`
  ⇒ **HBuilderX 导入它 → 发行 → 原生App-云打包**。HBuilderX **只做最后那一步**。
- 项目**不是** HBuilderX 创建的那种工程 —— 它是 CLI 工程，跑在 pnpm workspace 里，
  有 `vue-tsc` 类型门禁与 vitest 契约测试。
- **做界面重做时那个循环太慢**（build → 打包 → 装 → 看一眼）。开发界面要的是**真机实时预览**：
  `pnpm dev:app` 产出 `dist/dev/app` ⇒ HBuilderX「运行 → 运行到手机或模拟器」加载它。
  ⚠️ **这条本会话只从脚本与手册推出，未实测** —— 新会话要**先实测一遍**再把它写进设计。
- ⚠️ **HBuilderX 版本必须 ≥ 项目的编译器版本**（本项目 `@dcloudio/*` = `3.0.0-alpha-5020620260914001`
  ⇒ 要 **5.26**）。版本偏低时真机**白屏且无任何报错** —— 这个坑踩过。现场 `ReleaseNote.md`
  首条是 `5.26.2026091802` ⇒ 现在是 5.26 ✓。

## 4. 🔴 铁律：**前端是哑终端**（`docs/design.md` §12）—— 重做界面**不得破**

- 只依赖 `@fight-the-landlord/protocol`，**绝不** `import @fight-the-landlord/shared`
  （那会把游戏规则带进前端）；
- **不含**任何牌型判定、倍数计算、底分常量、叫抢规则；
- 每个入站消息先过 `validateInbound`；每个错误码走 `CLIENT_ACTION` 表分支；
  ⚠️ **`13004` 的唯一处置是「就地刷新快照」**，不是断线重连（§6.5）；
- `apps/client/test/source-boundary.test.ts` **机械地**扫 `src/**` 保证上面几条 ——
  **改界面时它必须一直绿**。

用户说的「协议不变」正是这条的核心。**重做界面时最容易犯的错，是为了好看/顺手把规则或协议逻辑挪进前端。**

## 5. 环境坑（本会话累积，新会话直接用）

- 🔴 **本机 DNS 缓存在路由器上** ⇒ `<DEV_HOST>` 可能指向旧机；**凡拿域名下结论先核
  `nslookup`**，否则会得出完全相反的结论（记忆 `windows-dev-env-quirks` 第 12 条）。
  实测 2026-09-26 已恢复正常（解析到 `<DEV_HOST_IP>`）。
- 🔴 **本机没有 `flock` 与 `script(1)`**（Git for Windows 不带 util-linux）⇒ 相关判据在本机
  **显式跳过**，只有 CI/Linux 能真跑。别把「本机绿」当成「全绿」。
- 🔴 **Windows 的 Git Bash 会改写参数里的路径**（`-C /data`、`-v DIR:/data`）⇒
  碰容器内路径的脚本要 `export MSYS_NO_PATHCONV=1`；宿主路径用 `cygpath -w`。
- 🔴 **测试用的 scratch 容器别以 `ftl-` 开头**，且别留 `c75b-*` 容器/网络。
- **改 JSON/Markdown 的字符串替换要验** —— 本会话有一次替换提前闭合了 JSON 字符串，
  留下悬空文本 ⇒ `SyntaxError`。**替换后要解析/复跑一次**。
- **`gh` 不在 PATH**（`/c/Program Files/GitHub CLI/gh.exe`）；`gh api` 的路径**别写开头斜杠**。
- **heredoc 里带反引号的提交消息会被 bash 吃掉** ⇒ 长消息写进文件再 `git commit -F <file>`。
