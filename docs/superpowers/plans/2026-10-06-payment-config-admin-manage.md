## 0. 用户裁决（2026-10-06，不得走样）

**「全面管理化，包括当前 .env 中的其它配置，能管理化就管理化。」**——即：支付相关配置尽量都做到**管理页可管**；`.env` 里其它能搬的也盘点搬。安全配套必须跟上（见 §2），不是裸搬。

## 1. 现状（背景，已核实）

- **业务参数已在配置中心**（第 26–34 键：开关/比率/档位/限额/时效）——管理页可改、热生效、审计齐。**这半边已达标，本片不动。**
- **`.env` 六项**（本片主对象）：
  | 变量 | 性质 |
  |---|---|
  | `ALIPAY_APP_ID` | 半公开标识 |
  | `ALIPAY_PRIVATE_KEY` | **机密**（base64 PEM） |
  | `ALIPAY_PUBLIC_KEY` | 半公开（支付宝公钥） |
  | `ALIPAY_SELLER_ID` | 半公开（商户 PID） |
  | `ALIPAY_GATEWAY_URL` | 非密（沙箱/生产切换用） |
  | `PAY_PUBLIC_BASE_URL` | 非密（部署身份，`https://<DEV_HOST>`） |
- **顺带盘点**（用户「其它配置能管理化就管理化」）：全栈 `.env` 逐项过一遍，给「可搬 / 不可搬（理由）」清单——**盘点结果先给用户看再定搬运范围**。
- 现实现：密钥**每次调用读 env**（payment-service `channel/alipay/client.ts`）；缺失/坏 ⇒ 15001、不阻塞启动——这层语义在搬运后要等价保留。

## 2. 安全硬要求（设计必须含，缺一即阻断级）

1. **加密存储**：私钥类值 at-rest 加密（密钥来源=服务端 `PAY_CONFIG_ENC_KEY` 之类，本身在 .env——根信任锚留 env 是底线）。
2. **不得进广播快照**：现有 `config.snapshot` 会推给全部订阅服务 ⇒ 密钥**绝不能**走它。需**专用下发通道**（payment-service 专属拉取/订阅）或「按服务可见性」机制——这是本片最主要的设计题。
3. **管理页不回显原文**：私钥字段「只写不可读」（保存后显示 `已配置 ✓` + 指纹/尾 4 位）；改=覆盖，清空=删除。
4. **审计脱敏**：现有 `config_changes` 存「旧值→新值」原文 ⇒ 密钥类变更**不得**落原文（落指纹+操作者+时刻）。
5. **轮换与泄露应对**：定义轮换流程（新密钥写入→生效→旧密钥作废）与泄露应对（渠道后台重签 + 流水核对），并入手册。
6. **权限**：密钥类写面收紧（`super_admin`；是否需要 finance 复核——可作产品问）。
7. 既有契约冻结面不动：payment 的调用语义（15001 语义、每次取值的时效）在迁移后等价；`slice-21`/`385` 单测等判据只增不减。

## 3. 建议范围（设计首稿据此展开；待评审）

- **移入管理面**：§1 六项 + 盘点后用户点过名的其它项。
- **保留 env**：根信任锚（如加密主密钥）、纯部署拓扑类（如 `PAYMENT_SERVICE_URL` 属网关拓扑，非支付配置——盘点时列「不可搬及理由」）。
- **不动的**：§1 已达标半边（26–34 键）。
- 产出物含：新配置键/新存储（加密列或独立表）· 管理页「支付渠道」编辑块（掩码写）· 下发通道 · 审计脱敏 · 迁移脚本（把现有 .env 值导入，一次性）· 手册更新（`first-deploy` 五步简化 + `alipay-onboarding.md` 对应改法）· 台账/闸同步（配置键计数 34→N、design.md 等——照支付片 §13.4 核销表惯例）。
