# 切片 7.2-P0 实施计划：堵住「读他人手牌」的 `?seat=` 通道

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让任何已认证用户**无法**读到非自己座位的手牌 —— 关掉 `GET /api/games/:roomCode?seat=<n>` 这条通道，并让网关无法被 `%3F` 走私出查询参数。

**Architecture:** 两处收口。①**网关**（`gateway.controller.ts`）：转发前对 5 个路径参数做 `encodeURIComponent` **并**用房间号形状白名单拒绝非法值（`10001`）——只编码不够，非法 roomCode 仍会被拼进下游 URL 与 Redis 键。②**game-service**（`game.controller.ts`）：`GET /api/games/:roomCode` 与 `GET /api/games/:roomCode/state` **删除 `@Query('seat')`**，座位只能由 `findSeatByUserId(session, X-User-Id)` 推导；非本局玩家 → `12004`。

**Tech Stack:** TypeScript / NestJS 10 / Vitest / socket.io 4 / 真实后端 conformance（`tools/conformance`）

**Spec:**
- `docs/design.md` §6.4（可见性裁剪：`hand` 是自己完整、他人只有张数）、§5.2（身份只从网关注入头取）、§5.3（越权防护：座位映射的唯一实现是「按 id 在 `GameSession.players` 中找座位」）、§7.1（网关路由表）、§11.2（错误码）
- `docs/superpowers/plans/deviation-ledger.md` —— 本条对应 **S2 / S8（部分关闭）+ N3**，见其 §1.3/§1.5 与 §2「独立小片 7.2」
- `docs/superpowers/plans/agent-briefs.md` —— 角色、工作区、已知环境事实

| 项 | 值 |

  **不含** N4（下游内部 token 覆盖面）、N5（`POST /api/games` 无鉴权）、S4（`robots/move` 吃整份 session）、
  S5（`bot-` 前缀出站）、S6（HTTP 限流）、S7（日志脱敏）、A6（删 `web/index.html`）、A7（网关超时）。
  这些留在 **7.2 完整片**，但**必须在切片 9 之前**做完 —— `docs/design.md` §A.3 写明
  「S1–S7 安全类偏差未清零前，MVP **不得对外部署**」。
- **R74 `?seat=` 直接删除，不加例外。** 生产代码**零调用方**（`game.client.ts` 只用 `X-User-Id`），
  而 §5.3 规定「座位映射的**唯一**实现是在 `GameSession.players` 中按 id 找座位」。
  保留它（哪怕加内部 token 才允许）就是保留**第二条身份通道** —— 与 R31 对 `X-Token-Jti` 的处理同理。
- **R75 网关必须做**双重**处理：`encodeURIComponent` + 房间号形状白名单。**
  只做编码不够：`%2F`、超长串、`..` 之类仍会被拼进下游 URL 与 Redis 键名，属于探测面。
  形状判定用 `/^[0-9A-Z]{6}$/`（与 `generateCode` 一致）；不合法 → `10001 BAD_PARAM`
  （**不得**返回 404/500 —— 那是把「参数非法」伪装成「房间不存在」）。
- **R76 客户端路径**不得**要求 `X-Internal-Token`**（这一点必须写进注释，防止后人「加固」时打断客户端）。
  网关的 `headersOf()` **只**转发 `userId`/`traceId`，不带内部 token ⇒ 若在 `GET /api/games/:roomCode`
  上加内部 token 校验，**客户端会全线 401**。真正的「仅服务间」边界是
  `POST /api/games`、`GET /api/games/:roomCode/snapshot`、`POST /api/robots/move`
  —— 它们的处置需要同时决定「网关是否继续暴露这些路由」，因此**留给 7.2 完整片**。
- **R77 conformance 用一个新用例名 `slice-07.2-security`**，**不回改**已合并的 `slice-07`
  （已通过的门禁用例保持稳定；新用例单独可跑、可负对照）。S8 的路由（`/:roomCode/state`）
  **不经网关**，需要新增 `GAME_URL` 环境变量（默认 `http://localhost:3003`）才能覆盖。

```ts
/** S8：`GET /api/games/:roomCode/state` **不经网关**，必须直连 game-service（compose 发布了 3003）。 */
export const GAME_URL = process.env.GAME_URL ?? 'http://localhost:3003';

export async function gameGetJson<T = any>(path: string, userId?: string): Promise<HttpResult<T>> {
  const res = await fetch(`${GAME_URL}${path}`, {
    headers: userId ? { 'x-user-id': userId } : {},
  });
  const text = await res.text();
  let parsed: Envelope | null = null;
  try {
    parsed = text ? (JSON.parse(text) as Envelope) : null;
  } catch {
    parsed = { code: res.status, message: text };
  }
  return { status: res.status, body: parsed };
}
```

- [ ] **Step 2: 写用例**

`tools/conformance/src/slices/slice-07.2-security.ts`，断言序列（复用切片 7 造房路径造出 3 人局，
取两个不同座位的账号 A、B）：

1. 3 人匹配成局 → 三方 `room.join` → 各自收到自己的 `game.deal`，记下 A 的 `seat`/`hand` 与 B 的 `seat`。
2. **取 A 自己的权威快照**（`game.resync`）作为参照：`A_hand`、`A_seat`。
3. **核心反例（S2）**：用 **A 的 token** 经网关请求 `GET /api/games/<code>?seat=<B.seat>` →
   断言返回的 `seat === A_seat` **且** `hand` 与 `A_hand` 逐张相等（**绝不能等于 B 的手牌**）。
4. **走私反例（N3）**：`GET /api/games/<code>%3Fseat=<B.seat>`（经网关）→
   断言 `code === 10001`（房间号形状被网关拒）**或**（若网关放行）返回的 `seat === A_seat`；
   两种结果都算通过，**唯一不可接受的是拿到 B 的手牌**。
5. **直连反例（S8）**：`gameGetJson('/api/games/<code>/state?seat=<B.seat>', A.id)` →
   同样断言 `seat === A_seat` 且 `hand` 与 `A_hand` 相等。
6. **非成员反例**：第 4 个账号（不在房间）经网关 `GET /api/games/<code>` → `12004`（HTTP 403）。

## 裁决补充（执行期落盘）

- **R78 批准 conformance 在 Task 2 第 5 步内**额外加两条**直连**断言**（`/state?seat=B` 与
  `:code?seat=B` 直连）。理由：实测**网关不转发客户端 query**（只插值 `req.params.roomCode`），
  因此「同源 `?seat=`」那条断言在有漏洞的镜像上**必然绿**、单独跑没有判别力；
  而 `%3F` 走私那条只覆盖「网关未编码」这半边。加直连断言后，**「只修网关、没删 `@Query('seat')`」
  这种半修也会红** —— 这正是切片 7 学到的「用例必须能抓住半修」。**不视为超出授权。**
- **R79 `GET /api/games/:roomCode`（与 `/state`）返回裸 `PlayerView`、不是 §11.1 信封** —— 这是**实测的既有形状**，
  本片**不改**（客户端走 WS，不用这两条 REST 路由；改形状会波及 `full-game.test.ts` 等既有用例）。
  已登记为对账表 **N6**，归**切片 9**（它要动游戏路由与出牌/过牌的错误码）。conformance 用 `isOkView()`
  按实际形状断言是**正确**做法，**不得**为迁就「信封」写法而放宽判据。

### 裁决补充 2（后端 Task 1 执行期，编号已让位 —— 它建议的 R78–R81 与上面两条冲突，故为 **R82–R85**）

- **R82 计划 Task 1 Step 4 的第一条断言与实测不符，已修正。**
  Express **已经解码**路径参数：控制器收到的是 `req.params.roomCode === 'ABC?seat=1'`（**不是** `'ABC%3Fseat=1'`）。
  因此 ① `encodeURIComponent` 永远看不到 `%3F`；② R75 的**形状闸先命中** → `10001` 且**不发起下游请求**。
  实测：`GET /api/games/ABC%3Fseat=1` → 修前 `{200, code 0, downstream: ['/api/games/ABC?seat=1']}`，
  修后 `{400, code 10001, downstream: []}`。后端按计划的**意图**实现并断言（10001 + 未打下游 + 无 `?seat=`），正确。
  同类：`ABC%2F123` → 修前下游 `'/api/games/ABC/123'`；`..%2F..%2Fetc` → `'/api/games/../../etc'` —— 都证明形状闸是必需的。
- **R83 第二道闸（`encodeURIComponent`）的行为断言不可行，接受后端用 spy 的写法。**
  白名单通过后输入恒为 `[0-9A-Z]{6}`，编码是**恒等变换** ⇒ 纯行为断言无法证明它存在（删掉也不会红）。
  后端用 `vi.spyOn(globalThis, 'encodeURIComponent')` 断言它被以 `'ABC123'` 调用，并**实测删掉调用即变红** —— 接受。
  同时采纳它的建议并在注释里写明：**形状闸是主控制，`encodeURIComponent` 是纵深防御**（R81 → 并入本条）。
- **R84 接受一处行为变化：形状非法的房间号现在得到 `10001`(400)，而不是透传下游后的 `12001`(404)。**
  这是 R75 的明确要求（不得把「参数非法」伪装成「房间不存在」）。
  已核对不受影响：`slice-07` 的 `'NOPE99'` 走 **WS**（不经过网关的 HTTP 路径闸），且其形状合法。
- **R85 后端独立复现了「直连伪造 `x-user-id`」并给出穷举核查，两者都采纳。**
  ① 它用**无 `Authorization`** 的 `curl http://localhost:3003/api/games/PWN001 -H 'X-User-Id: bob'` 读到了 bob 的 17 张手牌，
  与 conformance 的直连发现一致 ⇒ 进一步确认 **N4/N7 必须紧接着做**（见下一条的 P1）；
  ② 它**逐一核查了经网关的其余读手牌路径**（`/games/:code`、`/:code/state`、`/bid|play|pass` 的 `actAndView`→`findSeatByUserId`、
  `/snapshot`（需内部 token 且网关未暴露）、WS `game.view|resync|reconnect`（只传 `userId`）、
  Redis `game.events` 的 `seatViews`（逐座投递未整体广播））⇒ **经网关只剩直连端口这一条**。
  这个穷举结论把 S2/S8 的剩余面**收敛成一个明确的对象**，登记进对账表。
  ③ 它在修前镜像上留下副作用：直连建了局 `PWN001`（随 Redis TTL 过期）+ 注册了 1 个 `199` 开头账号（无害）。
- **R86 `RoomsService.generateCode()` 的边界（后端发现，低危）**：`Math.random()` 恰为 0 时
  `toString(36).substring(2,8)` 得到**空串**（概率 ~2⁻⁵³），该房间会被网关的形状闸判 `10001` 而永远进不去。
  属**独立小片 7.1**（room-service 收尾）的一个兜底改动（`padEnd(6,'0')`），本片不改。

### ⚠️ P0 的边界（必须写进汇报与交接）
conformance 实测证明：**P0 关掉的是公开路径**（经网关的 `%3F` 走私 + `?seat=` 覆盖），
