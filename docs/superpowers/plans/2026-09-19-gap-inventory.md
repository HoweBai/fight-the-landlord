## 第二部分：进行中 —— N39 的 App 运行期验证

**状态**：🟡 **根因已确认（2026-09-19），待执行修复** —— **不是代码缺陷，是工具链版本差**

### ✅ 根因（用户提供决定性证据）

设备端提示：

> **本应用使用 HBuilderX 5.26 或对应的 cli 版本编译，而手机端 SDK 版本是 5.24**

版本对照（均已实测）：

| 项 | 版本 | 来源 |
|---|---|---|
| 项目编译器 | **5.26** | `apps/client/package.json`：`@dcloudio/* @ 3.0.0-alpha-5020620260914001`；产物 `compilerVersion: "5.26"` |
| 本机 HBuilderX | **5.24**（build `2026081301`） | `E:\Softwares\HBuilder X\ReleaseNote.md` 首条 |
| 模拟器标准基座 SDK | **5.24** | 与 HBuilderX 一致（故日志说"基座已是最新版本，跳过更新"） |

⇒ **5.24 的标准基座拒绝加载 5.26 编译器产出的 bundle。**

**这一条解释了全部七条现象**：基座起来了（所以显示应用名"已启动"）→ 但拒绝加载我们的 bundle
⇒ 无 JS 执行、无控制台、无启动图、无联网、白屏。

⚠️ **判定**：这是**工具链版本差**，**不是本仓代码的缺陷**。N39 的 App 半边仍属「未验证」，
但**阻塞点已从"未知"变成"已知且具体"**。

### 修复路径（三选一）

| 路 | 做法 | 评价 |
|---|---|---|
| **①（推荐）升级 HBuilderX 到 ≥5.26** | `帮助 → 检查更新`，或跑安装目录里的 `Updater.exe`。升级后基座 SDK 随之更新 ⇒ 与编译器对齐 | **最自然**，且一次修好以后每次运行调试 |
| **② 云打包出 APK** | 绕开本地基座（DCloud 云端 SDK 是当前的）⇒ 拿到真 APK 装到设备上跑 | 也可行；**且云打包成功本身就闭合 N39 的 B3** |
| ❌ ③ 降级项目编译器到 5.24 | 要把 `@dcloudio/*` 降到 5.24 期的 alpha，会破坏已钉死的 Vite 5.2.8 peer 与整条工具链 | **不做** |

### 为什么"白屏"值得追到底（方法论备注）

这次排查**没有改一行代码**就定位了根因 —— 全程是**只读证据收集**：
产物静态检查（`node --check`、结构清单、悬空引用）→ HBuilderX 的落盘痕迹（`.hbuilderx/launch.json`、
`projects/*/setting.json`）→ 服务端旁证（网关 0 连接）→ 最后由**设备端的原生提示**一锤定音。

值得记住的是：**"没有报错"本身就是线索**。无 JS 执行 + 无控制台 + 无启动图，三者同时成立时，
问题不可能在 JS 里 —— 只可能是 **bundle 从未被加载**。这条推理链把搜索空间从"整个应用"缩到"加载环节"。
