## 4. 🔴 本次最重的一条：`GET /api/users/me` 在真栈上恒 401（已撤销）

**发现方式**：Task 6 的真浏览器实跑顺带核 Task 2 的收尾判据。

**事实**：`packages/api-gateway/src/gateway/proxy.gateway.ts` 的 `forward()` **逐字只组装四个头**
（`X-User-Id` / `X-Trace-Id` / `X-Token-Jti` / `X-Internal-Token`）—— **从不转发 `Authorization`**；
而 `packages/user-service/src/users/users.controller.ts` 挂的是 `@UseGuards(JwtAuthGuard)`
（裸 `AuthGuard('jwt')`，passport-jwt，**必须** Bearer）⇒ 经网关**恒 401**。
同一把 token 直打 user-service = 200。

**为什么探针与单测都看不见**：它走 `parse()` 折成 `10007`、**不产生 `console.error`**，
而顶栏只是**永久**显示一行「昵称加载失败」。

**用户裁决**：**不要这条路由** ⇒ 客户端改用**登录响应**里的 `phone`/`nickname`
（持久化进 `StoredSession`），显示仍是三级回落 `nickname → phone → userId`。
⇒ 已落地（Task 2R），网关那条路由**已撤**、`docs/design.md` §7.1 那句**已按实况改**
（网关**不暴露** `/api/users/*`；user-service 自己有 `@Get('me')`，只是网关不代理）。

⚠️ **这条曾经在文档里被写成「零服务端改动」**（我两次引用未核）—— 见 §5。
