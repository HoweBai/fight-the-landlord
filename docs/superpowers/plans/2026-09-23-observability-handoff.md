## 4. 环境纪律（**本片实测踩出来的**，别重踩）

1. ~~🔴 **改了任何服务源码 ⇒ 先在宿主 `pnpm exec turbo run build`，再重启容器**。~~
   **（2026-09-23 订正，`90fe1cd`）：宿主 dist 挂载已删除 ⇒ 这条纪律作废。**
   新形态：**改了任何服务源码 ⇒ 重建镜像再跑真栈判据** ——
   `DOCKER_BUILDKIT=0 docker compose build <svc> && docker compose up -d <svc>`。
   版本偏斜那条路径**结构性消失**（不再有宿主产物进容器）；但「旧容器跑真栈判据 = 空测」这条
   仍然成立（记忆 `windows-dev-env-quirks` 第 9 条）。
2. 🔴 **重建容器后先查 DI 陷阱**：`docker compose logs <svc> --since 30s | grep -i error`。
   `import type` 引被注入的 provider ⇒ 单测与 tsc 都看不见，**只有真容器会报**。
   ⚠️ 若报错在 `NestFactory.create` 阶段**只有 stack 没有消息**：Nest 的 `abortOnError` 默认 `true`
   ⇒ 用钩子把 `abortOnError` 关掉再跑真 `main.js` 才拿得到原文（命令在记忆 `windows-dev-env-quirks` 9b）。
3. ⚠️ **`checks.that(cond, msg)` 在成功时也打印 msg** ⇒ 消息必须写成**正面陈述**。
   写成"未找到 X / 实际 0 条"的口吻 ⇒ **绿行读起来像红**（本片实测踩过，四条全改）。
4. ⚠️ **真栈判据的「哪两行」必须先用 `docker compose logs` 核过**，不能凭"链路应该长这样"推断
   —— 本片我为此**写错三次**（spec §7.1-⑰）。**单测层结构上发现不了这类错**。
5. ⚠️ **别在与实现者同一包上并行跑测试**（`shared` 那条闸的固定名探针文件会撞 ⇒ 21 条全红，Obs-5）。
6. ⚠️ **grep vitest/turbo 的输出先剥 ANSI**（`sed -e 's/\x1b\[[0-9;]*m//g'`）——
   `Tests` 与数字之间夹转义序列，直接 grep 恒不匹配（`ci.sh` 的守卫踩过同一个坑）。
7. **三条已知假红**（记忆 `ci-flake-known`）：game-service 的 `game.controller`（绑真端口撞车）·
   user-service 的 `internal-token`（Windows 动态端口 ∩ Node 封禁端口表）· 上面第 5 条的闸。
   处置一律：**整包单跑确认**，别「重跑直到绿」。
