> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 §A.3 部署闸门剩下的安全/架构偏差一次清零 —— **S4 / S5 / S6 / S7 / A6 / A7 / N5 / N6 / R98（+ 两处执行期新发现）**，让「客户端可达的内部面」在网关层被删干净、下游边界有超时与限流、日志不再泄敏、编排的**生产形态**不再把内部服务与默认密钥交给宿主。

**Architecture:** 四层收口，从外到内：① **网关路由表回到 §7.1 逐字**（删掉 §7.1 没有的三条客户端可达路由：`POST /api/games`、`/api/robots/create`、`/api/robots/move`，删掉 `/` 静态页）；② **边缘加固**（HTTP 限流按已认证 `userId`、单 IP WS 并发连接 5、客户端自带身份头一律剥掉、下游超时 → `10007`）；③ **下游契约统一**（视图路由改 §11.1 信封、内部 token 错误码两层同码、日志经统一脱敏器出站）；④ **编排收口**（`docker-compose.yml` 变成生产形态：只发布 3000、去掉公开默认 token；开发/联调形态移入 `docker-compose.override.yml`，Compose 自动合并 ⇒ 既有门禁命令一字不改）。

**Tech Stack:** TypeScript / NestJS 10 / ioredis 5 / Redis ZSET 滑动窗口 / Vitest 2 / socket.io 4 + engine.io（`heartbeat` 事件）/ Docker Compose v2（`override` 自动合并 + `config --format json`）/ conformance（真实后端 + 真实 socket.io 客户端）

## 环境事实（执行前必读；踩了会浪费整轮）

1. **`docker-compose.yml`（生产形态）与 `docker-compose.override.yml`（开发形态）的合并方向**：不显式给 `-f` 时 Compose **自动合并** override（本机 v5.5.1 实测）。因此**日常命令一律不要加 `-f`**；只有 R98 的结构断言才显式 `-f docker-compose.yml`（并配 `--env-file /dev/null`，R147）。
2. **`docker-compose.yml` 把宿主 `./packages/robot-service/dist` bind-mount 进容器**（R99）⇒ 对 robot-service **重建镜像无效**；跑 conformance 前**必须先在主检出** `pnpm exec turbo run build --force`（症状：四个服务里**只有某一个「不听话」**）。
3. **`Dockerfile.user-service`** 的 `pnpm install` 必须 `--ignore-scripts`（否则 sqlite3 的 `prebuild-install` 无超时，本机实测卡 50 分钟），但必须紧跟 `node-pre-gyp --build-from-source` 重建 bcrypt，否则 user-service 以 `MODULE_NOT_FOUND` 崩溃重启。**本片不碰 Dockerfile**（只删 `Dockerfile.api-gateway` 的 `COPY web`）。
4. **门禁必须 `--force`**（`Cached: N cached / FULL TURBO` 是 turbo 回放缓存日志，不是真跑）；重建镜像用 **`DOCKER_BUILDKIT=0 docker compose build`**（本机三个 `registry-mirrors` 全挂，BuildKit 不回退上游）。
5. **本片要重建的镜像**：`api-gateway`（路由/限流/超时/日志）、`game-service`（信封/snapshot/日志）、`robot-service`（路由删除/日志）、`user-service`/`room-service`（只加日志 override）+ **主检出 `pnpm exec turbo run build --force`**（robot 的 bind-mount）。

`packages/api-gateway/src/http/rate-limit.ts`（**唯一的窗口实现**：HTTP 与 WS 连接两个维度都走它）：

```ts
import type { Redis } from 'ioredis';

/** §5.4：单用户 HTTP 请求 20 次 / 5 秒。 */
export const HTTP_RATE_LIMIT = { max: 20, windowMs: 5000 } as const;
/**
 * §5.4：单 IP 并发 WebSocket 连接 5 条。
 *
 * `ttlSeconds` 是**兜底**（§5.4 逐字：「对每个 IP 的连接 key 设 TTL 兜底，防止进程崩溃
 * 导致计数泄漏」）：正常路径靠 `disconnect` 的 `ZREM`，TTL 只负责清理崩溃残留。
 * 之所以 60s 够：连接存活时 engine.io 每 30s 一个 `heartbeat`，我们借它续期（见 proxy.gateway）。
 */
export const WS_CONN_LIMIT = { max: 5, ttlSeconds: 60 } as const;

export const httpRateLimitKey = (userId: string): string => `ratelimit:http:${userId}`;
export const wsConnRateLimitKey = (ip: string): string => `ratelimit:ws-conn:${ip}`;

/**
 * §5.4 的滑动窗口：`ZREMRANGEBYSCORE` 清窗外 → `ZCARD` 判定 → `ZADD` 记账。
 *
 * 判定与记账**必须**在同一个函数里：分成两个函数就会有调用方「只判不记」，
 * 于是限流静默失效（本仓已有前科：`acquireBot` 漏头只被 conformance 抓到，R70/R90）。
 * member 用 `now-随机`（与 room-service 的 `ratelimit:ws` 同形）——同一毫秒的多个请求不能互相覆盖。
 */
export async function hitHttpLimit(redis: Redis, userId: string, now: number = Date.now()): Promise<boolean> {
  const key = httpRateLimitKey(userId);
  await redis.zremrangebyscore(key, 0, now - HTTP_RATE_LIMIT.windowMs);
  const count = await redis.zcard(key);
  if (count >= HTTP_RATE_LIMIT.max) return true;
  await redis.zadd(key, now, `${now}-${Math.random()}`);
  await redis.expire(key, Math.ceil(HTTP_RATE_LIMIT.windowMs / 1000));
  return false;
}

/** 占用一条「单 IP 并发连接」名额。`false` = 超限 ⇒ 调用方拒绝握手。 */
export async function acquireWsConnSlot(redis: Redis, ip: string, socketId: string): Promise<boolean> {
  const key = wsConnRateLimitKey(ip);
  const count = await redis.zcard(key);
  if (count >= WS_CONN_LIMIT.max) return false;
  await redis.zadd(key, Date.now(), socketId);
  await redis.expire(key, WS_CONN_LIMIT.ttlSeconds);
  return true;
}

export async function releaseWsConnSlot(redis: Redis, ip: string, socketId: string): Promise<void> {
  await redis.zrem(wsConnRateLimitKey(ip), socketId);
}

/** 心跳续期：不续期的话 TTL 兜底会把**长连接**当成崩溃残留删掉（限流被绕过）。 */
export async function touchWsConnSlot(redis: Redis, ip: string): Promise<void> {
  await redis.expire(wsConnRateLimitKey(ip), WS_CONN_LIMIT.ttlSeconds);
}
```

`packages/api-gateway/src/http/http-rate-limit.middleware.ts`：

```ts
import { Inject, Injectable, type NestMiddleware } from '@nestjs/common';
import { ErrCode } from '@fight-the-landlord/protocol';
import type { NextFunction, Request, Response } from 'express';
import type { Redis } from 'ioredis';
import { REDIS } from '../auth/session.guard';
import { USER_ID_HEADER } from '../auth/identity-headers';
import { hitHttpLimit } from './rate-limit';

/**
 * §5.4 的 HTTP 维度（R141）：**单用户** 20 次 / 5 秒 → `10006` + HTTP 429。
 *
 * 两条边界写死在实现里：
 *  1. **公开路径不计数**：`x-user-id` 只有 `JwtMiddleware` 验签后才会被写入
 *     （R146 之后客户端自带的值在边缘就被剥掉），因此「有值」⇔「已认证」。
 *     给公开路径按 IP 计数是**凭空加维度**（§5.4 没有它），而且会打伤 conformance
 *     （`slice-07.1` 一次连发 20 个注册请求）。
 *  2. **Redis 故障 fail closed**（`10007` + 503）：与 R26 的会话白名单同一条理由 ——
 *     「计数不可用就放行」等于把限流变成静默可选开关。
 */
@Injectable()
export class HttpRateLimitMiddleware implements NestMiddleware {
  constructor(@Inject(REDIS) private readonly redis: Redis) {}

  async use(req: Request, res: Response, next: NextFunction): Promise<void> {
    const header = req.headers?.[USER_ID_HEADER];
    const userId = Array.isArray(header) ? header[0] : header;
    if (typeof userId !== 'string' || userId.length === 0) {
      next();
      return;
    }

    let limited: boolean;
    try {
      limited = await hitHttpLimit(this.redis, userId);
    } catch {
      res.status(503).json({ code: ErrCode.UPSTREAM_UNAVAILABLE, message: 'rate limit store unavailable', data: null });
      return;
    }
    if (limited) {
      res.status(429).json({ code: ErrCode.RATE_LIMITED, message: 'Too many requests', data: null });
      return;
    }
    next();
  }
}
```

`packages/shared/src/logging/redact.ts`：

```ts
/**
 * §5.5 的脱敏规则**唯一实现**（R142）。
 *
 * 为什么在 `shared` 而不是每个服务一份：规则是本片最容易漂移的东西
 * （一个服务补了手机号、另一个漏了手牌 = 静默泄敏）。Nest 适配层
 * （`redacting-logger.ts`）也放这里，但**不 import `@nestjs/common`** ——
 * `packages/shared` 的 tsconfig 是 `"types": []`，而且加依赖要动
 * `pnpm-lock.yaml`（协调者独占的根配置）。
 *
 * 覆盖面（§5.5 的表 + 对账表 S7 的手牌要求）：
 *   手机号 / JWT 全文与 Bearer / password(_hash) 键 / 内部头的值 / 手牌类键。
 * **不覆盖**：`X-User-Id`（§5.5 允许记录，排障需要）。
 */
export const REDACTED = '[REDACTED]' as const;

/** 手牌类键：命中就把整个数组换成只留张数的占位（牌面一律不落盘）。 */
const CARD_KEYS = 'hand|hands|cards|bottomCards|actionLog|playedCards|deck';

const CARD_LIST = new RegExp(`(["']?(?:${CARD_KEYS})["']?\\s*[:=]\\s*)\\[([^\\]]*)\\]`, 'gi');
const SECRET_KEY = new RegExp(
  `(["']?(?:password|passwd|pwd|passwordHash|password_hash|refreshToken|accessToken)["']?\\s*[:=]\\s*)("[^"]*"|'[^']*'|[^\\s,}]+)`,
  'gi',
);
const SECRET_HEADER = /((?:x-internal-token|x-token-jti)["']?\s*[:=]\s*)("[^"]*"|'[^']*'|[^\s,}]+)/gi;
const JWT = /\beyJ[A-Za-z0-9_-]{4,}\.[A-Za-z0-9_-]{4,}\.[A-Za-z0-9_-]{4,}\b/g;
const BEARER = /\bBearer\s+[A-Za-z0-9._~+/-]+=*/gi;
const PHONE = /1[3-9]\d{9}/g;

/**
 * 替换时**保留原来的引号风格**：JSON 日志里 `"password":"pw"` 换成 `"password":"[REDACTED]"`
 * 才仍然是合法 JSON（换成不带引号的 bare 词会让后续解析器炸，也会让日志看起来像坏了）。
 */
const maskValue = (value: string): string =>
  value.startsWith('"') ? `"${REDACTED}"` : value.startsWith("'") ? `'${REDACTED}'` : REDACTED;

const countCards = (list: string): string => {
  const trimmed = list.trim();
  const n = trimmed.length === 0 ? 0 : trimmed.split(',').length;
  return `"[REDACTED ${n} cards]"`;
};

export function redactText(text: string): string {
  if (typeof text !== 'string' || text.length === 0) return text;
  return text
    .replace(CARD_LIST, (_m, prefix: string, list: string) => `${prefix}${countCards(list)}`)
    .replace(SECRET_HEADER, (_m, prefix: string, value: string) => `${prefix}${maskValue(value)}`)
    .replace(SECRET_KEY, (_m, prefix: string, value: string) => `${prefix}${maskValue(value)}`)
    .replace(JWT, '[REDACTED_JWT]')
    .replace(BEARER, 'Bearer [REDACTED_JWT]')
    .replace(PHONE, (m) => `${m.slice(0, 3)}****${m.slice(7)}`);
}

/** 对象/数组先按键名脱敏，再交给 `redactText` 兜底（调用方可能直接 log 一个对象）。 */
export function redactValue(value: unknown, depth = 0): unknown {
  if (depth > 6) return REDACTED;
  if (typeof value === 'string') return redactText(value);
  if (Array.isArray(value)) return value.map((v) => redactValue(v, depth + 1));
  if (value && typeof value === 'object') {
    const out: Record<string, unknown> = {};
    for (const [k, v] of Object.entries(value as Record<string, unknown>)) {
      if (/^(password|passwd|pwd|passwordHash|password_hash|refreshToken|accessToken)$/i.test(k)) out[k] = REDACTED;
      else if (new RegExp(`^(${CARD_KEYS})$`, 'i').test(k)) out[k] = `[REDACTED ${Array.isArray(v) ? v.length : 0} cards]`;
      else if (/^(x-internal-token|x-token-jti)$/i.test(k)) out[k] = REDACTED;
      else out[k] = redactValue(v, depth + 1);
    }
    return out;
  }
  return value;
}
```

`packages/shared/src/logging/redacting-logger.ts`：

```ts
import { redactText, redactValue } from './redact';

export type LogSinkLevel = 'log' | 'error' | 'warn' | 'debug' | 'verbose' | 'fatal';
export interface LogSink { (level: LogSinkLevel, line: string): void }

export interface RedactingLogger {
  log(message: unknown, ...rest: unknown[]): void;
  error(message: unknown, ...rest: unknown[]): void;
  warn(message: unknown, ...rest: unknown[]): void;
  debug(message: unknown, ...rest: unknown[]): void;
  verbose(message: unknown, ...rest: unknown[]): void;
  fatal(message: unknown, ...rest: unknown[]): void;
  /** R148：**不可省** —— Nest 传 `logger` 数组时会无条件调它（见接口上方注释）。 */
  setLogLevels(levels: readonly string[]): void;
}

/**
 * §5.5 的 Nest 落地形态（R142）：把 Nest 的 `Logger` 输出接上一个**必然脱敏**的通道。
 *
 * ⚠️ 消费者（各服务 `main.ts`）用 `Logger.overrideLogger(createRedactingLogger(...))` 安装它；
 * 这里刻意**不 import `@nestjs/common`**：Nest 的 `LoggerService` 是结构类型，
 * 由**服务侧**（那里有 @nestjs/common）做类型检查，shared 侧保持零依赖。
 *
 * ⚠️ R148：`setLogLevels` + 级别过滤是**必需**的。`NestFactory.create(AppModule, { logger: [...] })`
 * → `registerLoggerConfiguration()` → `Logger.overrideLogger(数组)`，而那条分支写的是
 * `return this.staticInstanceRef?.setLogLevels(logger)`（可选链只挂在 staticInstanceRef 上）
 * ⇒ 缺这个方法 = 启动即 `TypeError`（api-gateway 正是唯一传 `logger` 选项的服务）。
 */
const LEVELS = ['log', 'error', 'warn', 'debug', 'verbose', 'fatal'] as const;

export function createRedactingLogger(sink: LogSink): RedactingLogger {
  /** `null` = 未配置级别（全放行）；Nest 传数组后再按它过滤。 */
  let enabled: readonly string[] | null = null;

  const emit = (level: LogSinkLevel, message: unknown, rest: unknown[]): void => {
    if (enabled && !enabled.includes(level)) return;

    // Nest 的约定：最后一个可选参是 context（`new Logger('RoomService')`）。
    const context = typeof rest.at(-1) === 'string' ? (rest.at(-1) as string) : '';
    const extra = typeof rest.at(-1) === 'string' ? rest.slice(0, -1) : rest;
    const body = [message, ...extra]
      // R148：Nest 的实例 `error(message)`（只有 context）会传成 `[undefined, 'Ctx']`，
      // 而 `JSON.stringify(undefined)` 返回 **undefined**（不是字符串）⇒ 不过滤会留尾随空格。
      .filter((part) => part !== undefined && part !== null && part !== '')
      .map((part) => (typeof part === 'string' ? redactText(part) : redactText(String(JSON.stringify(redactValue(part))))))
      .join(' ');
    sink(level, context ? `[${context}] ${body}` : body);
  };

  return {
    log: (m, ...rest) => emit('log', m, rest),
    error: (m, ...rest) => emit('error', m, rest),
    warn: (m, ...rest) => emit('warn', m, rest),
    debug: (m, ...rest) => emit('debug', m, rest),
    verbose: (m, ...rest) => emit('verbose', m, rest),
    fatal: (m, ...rest) => emit('fatal', m, rest),
    setLogLevels: (levels) => {
      enabled = levels;
    },
  };
}
```

```ts
  step('③ 运行期 fail-closed：空 token ⇒ 服务拒绝启动；给了值 ⇒ 起得来');

}
```
