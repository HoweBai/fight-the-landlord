# 支付片 实施计划 v1.1

> ⚠️ **历史文档（2026-10-06 注）**：本计划的渠道密钥 env 注入面（`ALIPAY_*` / `PAY_PUBLIC_BASE_URL`，见 Global Constraints「密钥」条与各任务卡）已由「支付配置管理化片」**退役取代**（渠道六值 → config-service 加密存储 + 管理页「支付渠道」+ `config.payChannel.get` 每调用拉取）。实施/运维请以该片规格（`docs/superpowers/specs/2026-10-06-pay-channel-admin-spec.md`）与手册为准。

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 交付支付片全链——新服务 `payment-service`（第 8 个 Nest）：充值（下单 → 支付宝手机网站支付 → 回调验签 → `currency.apply` 入账）· 退款（申请即冻结 → 人工审 → 渠道原路退 → 回滚面）· 提现（申请锁内冻结 → 人工审 → 线下打款台账 → 超时回滚）· 分池「可离场额度」· 管理面三队列 + 审计第六源 · 客户端钱包页（第 6 页）· 监控面（10 指标 + 5 告警 + 07-payment）· conformance `slice-21`（stub 支付宝双向金标）。

**架构：** 新服务 `payment-service`（HTTP 3007 / metrics 9007 / 零被调 RPC；共享库五表 + `migrations_payment`）；资金唯一写边仍 = currency-service `currency.apply`（本片 +5 source + 新增只读 `currency.withdrawable.get` 承载 cap=可离场额度，**零写路径改动**）；回调 = edge 公开路由直连 + **RSA2 验签唯一信任入口**；资金动作纪律 = 行锁串行化 + claim 先行 + holding 只解析不回溯 + 同锚重试扫描（设计 §2.4/§2.5）。

**技术栈：** NestJS 11 · TypeORM 0.3 + mysql2（裸 SQL）· Redis（回调桶）· `node:crypto` RSA2（**零新依赖**）· prom-client · vitest · conformance（`slice-21` + `ftl-alipay-stub` 容器）· uni-app（客户端钱包页）· Admin 静态页（无构建）。
